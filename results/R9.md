# R9: 42 unseen worlds, and the first grounding measurement

**Date:** 2026-09-20. **Hardware:** one RTX 4090, RunPod community, $0.34/hr,
~6.5 GPU-hours. **Cache:** `models/tiny/data_cache_ho42`, structural binding,
`s5_plain` train / `s5_holdout_both` holdout. **Script:**
`models/tiny/run_step1.sh` at `TAG=ho42`, both arms x three seeds, 12 epochs,
batch 64, 4,812 steps per arm-seed. **Scored on the laptop** (the sandbox needs
Node; `pack.py` leaves it behind by design).

Two questions, one run. R8 left the control arm's unseen-world spread at
**74-95%** across three seeds and built the injection plan on that instability.
`results/GROUNDING.md` then found that every suite in the tree identifies the
called tool by its type signature alone, so no unseen-world number anywhere in
`R3/R7/R8` distinguishes tool grounding from type inference. This run measures
both at once, because the holdout carries the same 8,000 tasks twice: once
plain, once with every tool given signature-identical siblings whose
descriptions are the only separator (`harness/decoys.py`).

---

## 1. The headline

Six models, each scored on both halves of the same holdout. Same tasks, same
reference programs, same 42 worlds nothing has ever trained on; the halves
differ only in whether the signature identifies the tool.

| arm | half | goal | seed spread | `same_tool` | shape-only null |
|---|---|---|---|---|---|
| control (ar) | plain | **70.4%** | **1.8 pt** | 86.9% | 100.0% |
| control (ar) | decoy | 46.0% | 3.2 pt | 62.8% | 43.6% |
| diffusion | plain | **67.7%** | **1.0 pt** | 88.3% | 100.0% |
| diffusion | decoy | 42.0% | 3.0 pt | 59.8% | 43.6% |

Per-arm, over three seeds:

| arm | margin over shape-only | plain -> decoy drop | `decoy_called` |
|---|---|---|---|
| control (ar) | **+19.2%** [+18.2, +19.8] | -24.0% [-25.0, -22.8] | 29.7% |
| diffusion | **+16.1%** [+14.1, +18.1] | -28.5% [-30.3, -26.5] | 32.1% |

## 2. R8's variance question is answered, and the answer dissolves it

**The control arm's unseen-world spread is 1.8 points, not 21.**

R8 measured 74-95% by holding out `bookstore` — one world, 275 rows, 0.96% of
the training data, carved from inside the training pool. Over the 42 worlds
reserved for this since S2, the same arm at the same three seeds spans
69.3-71.2%. The diffusion arm spans 1.0 point.

So the instability was the measurement, not the encoder. An unlucky world and a
seed-unstable model are indistinguishable at n=1, and R8 said as much; this
settles which it was.

**This weakens the premise of the injection plan.** Step 5 of
`.claude/plans/merged-state-2026-09-20.md` exists to narrow a control spread
that is already narrow. Whatever else open-schema injection is worth — and the
rejection-pressure question in that plan is untouched by this result — "it
stabilises the control arm" is no longer a reason to run it.

## 3. The first grounding number this project has been able to take

**The margin over the shape-only null is +19.2 points for the control arm and
+16.1 for diffusion, stable across seeds.**

`chance_tool_sig` is the score a model gets by mapping English to a type shape
and picking uniformly inside the signature collision group, having read no
description at all. On the decoyed half it is **43.6%**. Both arms beat it, at
every seed. That is positive evidence that the model reads something the type
signature does not carry — the first such evidence in this codebase, and it is
available only because the suite can now pose the discrimination.

Read against the flat `chance_tool` instead — a uniform pick over all 41 tools,
**2.4%** — the control arm's 62.8% looks like twenty-six times chance and means
nothing. That gap between 2.4% and 43.6% is the whole of `GROUNDING.md` in one
line, and it is why `models/tiny/diagnose.py` now reports both.

**What the margin does NOT establish:** whether the thing being read is the
**description** or the tool **name**. A decoy is `snooze_card` beside a real
`archive_card` — different verbs, both meaningful — so a request saying
"archive this card" is matched by the name alone. `ho42_name_probe.py` splits
reference calls by whether the competing siblings are adversarially named
(`foo17`) and finds only a **+5.3 point** advantage when they are (n=288, about
1.9 sigma), which rules out "the model only works when its competitors are
obviously fake" and rules out nothing else.

The instrument that would settle it is `ablate_desc.py`: permute descriptions
among tool lines, leaving every symbol, signature, effect and name in place,
and regenerate. **It does not support structural binding** — a structural cache
holds per-line tensors, so a permuted context must be re-split and re-encoded
per row (`prep.encode_structural`), which is not written. Until it is, "the
model reads schemas" remains unsupported in its strong form. H4 is better off
than it was, and still not established.

## 4. The arms swap places when the shortcut is removed

On the plain half the diffusion arm selects tools **better** than the control
(88.3% against 86.9%) while reaching the goal **worse** (67.7% against 70.4%).
On the decoyed half it selects tools worse (59.8% against 62.8%), drops further
(-28.5 against -24.0) and calls a decoy more often (32.1% against 29.7%).

**The diffusion arm leans harder on the type-signature shortcut than the
control does.** That ordering is invisible on any suite in `results/` before
this one, because on a 100%-unique suite there is no score a shape matcher
cannot reach. It does not overturn R8's arm comparison — diffusion was already
behind on goal — but it adds an axis on which it is behind for a reason.

## 5. What `decoy_called` caught

Roughly **30% of decoyed tasks call a signature-identical sibling** that
appears in no reference program. Outcome scoring alone would have hidden part
of that: a decoy READ returns an empty list, an empty list is the legitimate
trigger for check-then-decline, so a model that picks a decoy list tool and
abstains scores a correct abstain having chosen the wrong tool
(`GROUNDING.md` section 8). The column is recorded and not gated, so every
number already in `results/` keeps its meaning.

## 6. Cost, and two things that would have made it much larger

$2.22 of a $20 balance, including $0.14 on a first pod that had the GPU visible
to `nvidia-smi` but `torch.cuda.is_available()` false — `/dev/nvidia3` present
with no `/dev/nvidia0`, a host-side device-node mismatch a container restart
did not clear. **Check CUDA before uploading anything.**

Two defects found before the meter mattered:

- `selftest.sh` would have died on its first command on the pod. `pack.py`
  ships neither the Node sandbox nor the themed worlds, and steps 1 and 3
  execute programs; `set -euo pipefail` turned an expected absence into a dead
  gate. Both are now skipped with a reason, and steps 2-6 still run.
- Holdout generation would have dominated the bill. `evaluate.py` generates one
  row at a time and `pod.md` sized its two-hour estimate on a **275-row**
  holdout; this one is **15,248**. `--limit` alone could not help, because the
  plain rows come first. `--id-contains` / `--id-not-contains` plus a 2,000-row
  cap per half cut that stage ~3.8x.

Measured, against the estimates in `pod.md` and `models/tiny/README.md`:

| | predicted | measured |
|---|---|---|
| VRAM at batch 64 | 15.9 GB | **18.9 GB** |
| step time | "well under 0.19 s" | **0.53 s** |
| processes on a 24 GB card | 1 | 1 (confirmed; 2 would need 37.8 GB) |

The VRAM prediction was 19% low and the step-time prediction was ~2.8x low. The
step-time ratio was estimated on this laptop's CPU at 1.19x; the real GPU ratio
is nearer 2.8x, which is the README's own warning about this box holding.

## 7. Reproducing

```bash
# laptop
bash results/logs/gen_s5_holdout.sh 0 typed 1:2      # data/s5_holdout_decoy.jsonl
python - <<'EOF'                                      # data/s5_holdout_both.jsonl
import json
from pathlib import Path
with Path("data/s5_holdout_both.jsonl").open("w", encoding="utf-8", newline="\n") as fh:
    for src, suf in (("data/s5_holdout.jsonl", ""), ("data/s5_holdout_decoy.jsonl", "+decoy")):
        for line in Path(src).open(encoding="utf-8"):
            if suf:
                r = json.loads(line); r["id"] += suf
                line = json.dumps(r, ensure_ascii=False) + "\n"
            fh.write(line)
EOF
cd models/tiny
python prep.py --corpus ../../data/s5_plain.jsonl --limit 30000 --max-line 80 \
    --holdout-corpus ../../data/s5_holdout_both.jsonl --out data_cache_ho42
bash selftest.sh data_cache_ho42
python pack.py --cache data_cache_ho42 --out pod_bundle_ho42.tar.gz

# pod
tar xzf pod_bundle_ho42.tar.gz && cd tiny
python -m pip install tokenizers          # `pip` and `python` differ on the image
bash selftest.sh data_cache_ho42
TAG=ho42 CACHE=data_cache_ho42 SEEDS="0 1 2" bash run_step1.sh > step1_ho42.log 2>&1

# laptop, after bringing back out/
bash score_ho42.sh out data_cache_ho42
python ho42_name_probe.py out/ho42_ar_s0_holdout_decoy.jsonl data_cache_ho42
```
