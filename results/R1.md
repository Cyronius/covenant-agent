# R1 — Does the IR fit the job?

**Question (PLAN §3):** Can Agent Core express the curriculum compactly,
without escape hatches?

**Verdict: PASS.** Expressiveness: 99.9% compile, zero inexpressible tasks,
98.5% goal_success. Token cost: 0.269 under the restated bar (owner ruling
2026-08-30 — AC counted under the planner's own vocabulary, JS under a
standard subword tokenizer; see §Token cost). Under the original
same-tokenizer-both-sides wording the ratio was 0.545 vs ≤ 0.40 — that
miss is recorded here, not hidden; the bar was restated because it measured
GPT-2's vocabulary rather than the planner's emission cost, per PLAN §3.

## Setup as actually run

- **Tasks:** 1,000, generated `python -m data.gen --levels
  0:5,1:5,2:12,3:12,4:12,5:12,6:12,7:12,8:12,9:5,10:5 --n 1000 --seed
  20260829 --drop-noops --out data/r1_tasks.jsonl`. The `--drop-noops`
  filter discarded 268 degenerate tasks during generation (mutating-effect
  programs that leave state unchanged, e.g. "close the closed tickets") —
  a 21% raw defect rate that must be fixed before R3 corpora (see
  §Generator defects).
- **Author (strong model):** Claude Sonnet subagents, 40 batches of 25
  tasks + a PAUSE-continuation pass, one-shot (no compiler feedback, no
  retry). Few-shot material: `spec/agent_core.md` + `spec/examples/`.
  Authors saw only the request and the T/F/C symbol tables
  (`input_text`) — never the generator's reference program or expected
  state. Each task also received a hand-written **idiomatic JS
  equivalent** from the same author (invented camelCase tool names, real
  field paths, real literals) as the token-comparison target.
- **PAUSE protocol:** authors ended check-in tasks at `PAUSE`; the harness
  executed segment 1, returned actual register values, and a second
  authoring pass wrote the continuation from that state. 48 tasks
  round-tripped this way.
- **Scoring:** `harness/r1.py` → `harness.run.run_task` (the F3 pipeline,
  source of truth). Git SHA `2e62976` + uncommitted R1 tooling; metrics in
  `results/r1_metrics.jsonl`.
- **Tokenizer:** GPT-2 BPE (`tiktoken`) on both Agent Core and JS;
  whitespace counts logged alongside.

## Token cost (the failed half of the bar)

Median tokens per program, same 999 compiled tasks:

| Counting | AC | JS | ratio (median) |
|---|---|---|---|
| GPT-2 BPE both sides (the stated bar) | 50 | 91 | **0.545 — FAIL vs ≤ 0.40** |
| Whitespace both sides | 25 | — | 0.774 (JS whitespace undercounts; not meaningful) |
| AC at 1 token/symbol vs JS GPT-2 BPE | 25 | 91 | **0.269 — passes** |

Why the stated measurement fails: GPT-2 BPE splits every IR symbol
(`T4`, `F12`, `r0`, `C1`) into ~2 tokens while compressing JS keywords and
boilerplate into single tokens. The stated bar therefore measures GPT-2's
vocabulary, not the IR. The third row is the cost model the system is
actually designed around — the R3 planner has a fixed vocabulary where
every IR keyword/symbol is one token (that is the point of numbered
registers and T/F/C symbols), while a JS-emitting agent of any size pays
subword rates on real identifiers.

**Owner ruling (2026-08-30):** the bar is restated as "median AC tokens
under the R3 vocabulary ≤ 40% of the JS equivalent under a standard
subword tokenizer" — **0.269, PASS**. The original same-tokenizer result
(0.545, a miss) stays recorded above per PLAN §14; the restatement is
noted in PLAN §3 with its motivation. Raw per-task counts in
`results/r1_metrics.jsonl` make either bar re-checkable without
re-running.

## Failure catalog (all 16, each reviewed by hand)

15 goal failures + 1 compile failure. **None are IR expressiveness
failures.** Three categories of generator-English defect (11 tasks) and
two categories of genuine author error (5 tasks):

1. **"a couple of times" → RETRY count mismatch (6 tasks, L8).** The
   template maps "a couple" to `RETRY 3`; every author wrote `RETRY 2`
   (arguably the better reading). Generator fix: verbalize the exact
   count.
2. **L4 ordinal implicit scope (3 tasks).** "Archive the card with the
   second earliest due date" — the reference silently filters to
   unarchived cards first; the English never says so. Authors split on
   inferring it (some did, via the otherwise-unused BOOL constant — the
   constants table leaks scope the English omits). Generator fix:
   verbalize the filter.
3. **Garbled compound phrasing (1 task, L3).** "mark all the customers …
   unless they are on the enterprise plan delinquent" — misplaced
   modifier; author over-interpreted with an extra OR clause.
4. **Temporal comparison direction (3 tasks, L3) — genuine author
   errors.** "signed up more than 510 days ago" requires
   `timestamp LT cutoff`; authors wrote `GT`. The classic
   direction-of-time bug, and direct evidence for R6's temporal
   adversarial category.
5. **Schema misread / TRY scope (2 tasks) — genuine author errors.** One
   wrong F-symbol (the sole compile failure, caught statically as
   `UNKNOWN_FIELD`), and one TRY block wrapping only the send when the
   injected fault hit the fetch ("fetch X and message them; if that
   fails…" — ambiguous antecedent; the request wording splits authors
   ~50/50 across the corpus).

Both `unnecessary_destructive` calls sit inside categories 2/4 — scope
errors on destructive ops, exactly the case R7's effect penalty targets.

## Independent semantic spot-check

94 programs (stratified across all levels) re-reviewed by independent
verifier agents that saw only request + schemas + program (never the
reference), plus orchestrator hand-review of all 16 failures, the pilot
batch, and the sanity set — >110 programs checked in total.

Verifier raw verdicts: 87 correct, 6 wrong, 1 defensible-ambiguous.
Adjudication of the 6 "wrong": 5 are verifier false positives — all the
same complaint (TRY wraps only the fetch, so a *send* failure would go
uncaught) on programs structurally identical to their references, i.e.
the "if that fails" English ambiguity again, not an authoring defect; 1 is
the already-catalogued temporal-direction failure, which goal_success had
caught. **Zero new "right state, wrong semantics" cases** — on this
sample, harness goal_success and independent semantic judgment agree
everywhere the English itself is well-formed.

## IR awkwardness observations (candidates listed for review — PLAN §12; nothing added)

- **No boolean grouping/parentheses.** `unless (A and B)` must be
  distributed manually across AND/OR clauses. One author self-flagged
  this; it produced the over-interpretation in failure category 3.
  Candidate: parenthesized clause groups, or a NOT-group form.
- **No join primitive.** Parent-child correlation ("every customer's open
  tickets") requires nested FOREACH + per-iteration FILTER with a
  field-equality clause. Expressible and authors used it correctly;
  verbose at ~3 extra instructions per join.
- **TRY scope granularity.** The grammar allows multi-call TRY bodies, but
  the English "if that fails" has no way to signal intended scope;
  see failure category 5. This is as much a data-generation issue as an
  IR one.
- **`PAUSE` discipline worked** once the authoring protocol was explicit
  (PAUSE must terminate the segment). The one pilot violation
  (continuation written inline after PAUSE) was correctly rejected by the
  `UNREACHABLE` diagnostic — the static checks earn their keep.

## Generator defects to fix before R3 corpora (data/gen, not IR)

1. 21% raw no-op rate (`--drop-noops` now filters; better: fix the
   recipes' precondition sampling).
2. Unverbalized scope in L4 ordinal recipes; unverbalized retry counts in
   L8; misplaced modifiers in L3 compound templates.
3. L6 "for every user, do X to each of their Y" template: outer loop
   frequently vacuous (fixed-constant filter), flagged by 8+ authors;
   authors legitimately split between nested and flattened forms (same
   final state, different tool_efficiency).
4. The CONSTANTS table leaks reference scope (an unused `false` constant
   implies an archived-filter). Either verbalize the scope or add genuine
   distractor constants.

## What changes because of R1

- **R1 is closed as a PASS** (owner ruling on the token bar, 2026-08-30).
  Nothing downstream is blocked: the IR held at 99.9% compile / 98.5% goal
  with zero escape hatches, PAUSE round-trips work, and static diagnostics
