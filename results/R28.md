# R28: a looped draft plus a left-to-right refiner does not beat a deeper left-to-right decoder

**Date:** 2026-10-03. **Branch:** `description-reading` (uncommitted). **Spend:**
about $6 (one secure A40, pod `4wwrltcla8yppw`, deleted after a verified pull);
balance $21.74. **Plan:** `.claude/plans/staged-decoder-experts.md`, steps 0a,
0b, 1 and 2. The owner: "ok, i reloaded runpod . do it". Step 2's gate failed,
so steps 3-4 (experts, bolt-on) did not run, as the plan says.

**Terms.** *Left to right*: today's decoder, one program slot at a time, each
slot seeing the ones before it. *Draft stage*: a diffusion stage that fills
all 64 slots at once from a blank canvas, looped with the same weights.
*Refiner*: a left-to-right stage that reads the context and the draft.
*Loads*: weight loads per program on the NPU (encoder counts as one).
*Early exit*: skip the refiner when the draft's lowest slot confidence clears
a threshold. *Arms*: `base` left to right, 4 layers; `ctrl6` left to right, 6
layers (the parameter control); `draft` one draft stage, 4 layers x 4 loops,
no refiner; `DR` draft 4x4 then refiner 2x1 (the design); `D2R` two draft
stages 2x4 then refiner 2x1; `DRx` DR trained with mistakes put into its
drafts (added mid-run, below). All on the D3 corpus, two seeds each.

## The result

1. **The gate fails for every staged arm.** The plan's gate: DR beats ctrl6
   by 2 points or more, on both seeds, on plain or on the held-out worlds.
   Goal %, seed 0 / seed 1:

   | arm | plain | vs ctrl6 | held-out worlds pooled (1,200 turns) | vs ctrl6 |
   |---|---|---|---|---|
   | ctrl6 | 62.1 / 64.2 | | 15.9 / 17.2 | |
   | DR | 65.0 / 61.7 | +2.9 / **-2.5** | 19.5 / 17.5 | +3.6 / **+0.3** |
   | D2R | 65.5 / 63.0 | +3.4 / **-1.2** | 18.2 / 17.5 | +2.3 / **+0.3** |
   | DRx | 61.9 / 67.5 | **-0.2** / +3.3 | 14.1 / 16.8 | **-1.8** / **-0.4** |

   Seeds of the same arm differ by up to 6 points on plain, so the staged
   arms and ctrl6 are tied on the halves that are new to every model.
   (Held-out worlds pooled = boatyard, rooms_after, house, coursebuilder,
   telecom, played turn by turn.)

2. **On worlds the models trained on, the staged decoder is much worse.** Test
   split (seen worlds): ctrl6 84.0, DR 64.9, D2R 70.7, DRx 67.2. Data rows
   alone: ctrl6 87.5, DR 65.0. The loss is all in constants. Validation
   accuracy, last epoch:

   | | keyword | tool | field | constant |
   |---|---|---|---|---|
   | base | .996 | .95-.96 | .96-.97 | .88-.90 |
   | ctrl6 | .995 | .96-.97 | .95-.97 | .90-.92 |
   | draft alone | .97 | .92-.94 | .87-.91 | .71-.73 |
   | DR | .995 | .95-.96 | .95-.96 | .77-.78 |
   | D2R | .995 | .95-.96 | .95 | .79-.83 |

   The refiner's constants sit near the draft's, not near left to right's,
   even though the refiner can see the whole context.

3. **Why: the refiner learns to copy the draft.** It keeps the draft
   unchanged on 63-73% of programs. When it does change something it fixes
   more than it breaks (DR seed 0, test: 195 fixes, 81 breaks), so it is not
   useless. But on the training rows the draft is almost always right, so
   copying is what training rewards, and on new rows the copied mistakes stay.

   *The fix tried (DRx):* during training, a quarter of the draft's slots
   were swapped for another pointer of the same kind (a different constant
   for a constant) and 5% for random tokens, so copying stops paying. It did
   not change the habit: still 65-73% kept, constants .78-.79, test 67.2 vs
   DR's 64.9 (inside seed noise).

   *A deviation that bears on this:* the plan trained the refiner on a frozen,
   already-trained draft stage. I trained both together in one run, to keep
   it to one run per arm. The plan's version has the same hole (a draft
   trained on the same rows is right on them too). The fix that would close
   it is drafts from a draft stage that never saw the row: train it on half
   the rows, draft the other half, and swap. Not tried.

4. **Two looped draft stages beat one** (D2R over DR: test +5.8, constants
   +.01 to +.06, plain +0.8). One trip of the draft alone is 6 points under
   left to right on plain and 27 under on test.

5. **The early exit works on rows like the ones it was tuned on, not on new
   worlds.** Thresholds were set on validation rows: the lowest confidence at
   which drafts that exit are as accurate as the refined programs.

   | run | exits (val) | plain, refine always -> with exit (exit share) | loads per program |
   |---|---|---|---|
   | DR s0 / s1 | 41% / 57% | 65.0 -> 65.1 (49%) / 61.7 -> 61.1 (66%) | 2.59 / 2.43 |
   | D2R s0 / s1 | 41% / 59% | 65.5 -> 65.5 (45%) / 63.0 -> 62.5 (67%) | 3.59 / 3.41 |
   | DRx s0 / s1 | 54% / 37% | 61.9 -> 62.1 (58%) / 67.5 -> 67.7 (44%) | 2.46 / 2.63 |

   At most 0.6 points lost on plain with half the programs exiting. On the
   coursebuilder exam (a page app it never saw) the same thresholds cost 4-8
   points for DR (99 -> 91, 71 -> 55 of 193). Counted in weight loads, a
   staged program costs more: 2.4-3.6 against left to right's 2. Counted in
   steps that must run one after another, it is much faster (point 9).

6. **One held-out world favours the staged decoder, and it is a weak
   signal.** House, never trained, 445 turns: every staged run scores
   40-72 goals, every left-to-right run 1-48 (ctrl6 3 / 39, base 1 / 48).
   That fits R8's finding that diffusion transfers better to a new world.
   Against it: house is one of five held-out worlds, its R24 reference
   answers come from a player that sees the whole map (the planner sees only
   the brief), left to right's own seeds swing from 1 to 48 on it, and
   coursebuilder goes the other way (ctrl6 110 / 86, DR 99 / 71).

7. **D3 (step 0b): adding rows without removing any costs the old halves
   nothing we can measure.** R24 held the corpus at 30,000 rows, so every new
   row pushed an old one out. D3 kept every old row and added all 9,034 new
   ones. The holdout halves are the same 6,472 rows for both:

   | | plain | decoy | flip | cluttered |
   |---|---|---|---|---|
   | old corpus (clt_base) | 62.4 (59.2-65.5) | 34.5 (31.6-37.4) | 20.9 (18.2-23.5) | 58.7 (56.2-61.2) |
   | D3 (d3_base) | 63.8 (62.6-65.1) | 32.8 (31.9-33.6) | 18.9 (16.5-21.2) | 56.0 (53.6-58.5) |

   Every difference sits inside the seed ranges, and the new kinds are learned
   (boatyard 2 / 0 -> 23 / 31, rooms_after 0 / 0 -> 47 / 38, coursebuilder
   1 / 0 -> 55 / 114). The plan's reading: R24's 3-12 point losses were rows
   pushed out, not interference, so experts aren't needed to stop
   forgetting. Their case shrinks to capacity and bolt-on. (The test split
   isn't compared: D3's includes the new kinds.)

8. **The router (step 0a) passes, but its test is easy.** Trained on the
   ctrl6 and DR encoders, it picks the right type on 100% of the held-out
   worlds and the 70 demo requests (gate: 90% and 80%). On the DR encoder,
   telecom drops to 82%, and the top-two fallback covers the rest. But each
   held-out world's type shows on its surface (a world brief, page tools,
   data tools), and all 70 demo requests turned out to be data requests, so
   this only shows that routing these three types is not a bottleneck. Types
   that share a surface (report vs data, when built) would be the real test.

9. **Speed (added after the owner asked; modelled, not measured).** Left to
   right runs its whole decoder once per program slot, one slot after
   another: the average program here takes 20-24 slot steps. The draft
   runs its 16 layer passes (4 layers x 4 loops) over all 64 slots at once,
   and the refiner adds 2 layers per slot only when the draft doesn't exit.
   Counting layer runs that must happen one after another, from the real
   program lengths, with the early exit:

   | | plain: goal / steps in a row (mean, median) / layers of weights moved | test: goal / steps / weights |
   |---|---|---|
   | base (4 layers) | 62.6, 65.1 / 95, 84 / 4 | 76.3, 82.4 / 80, 60 / 4 |
   | ctrl6 (6 layers) | 62.1, 64.2 / 143, 126-132 / 6 | 84.8, 83.3 / 120, 90 / 6 |
   | DR | 65.2, 61.1 / 36-45, 16-33 / 4.7-5.0 | 65.8, 63.3 / 37-43, 16-36 / 4.9-5.2 |
   | D2R | 65.5, 62.5 / 35-47, 16-38 / 4.7-5.1 | 72.0, 68.8 / 36-43, 16-36 / 4.9-5.2 |

   So the staged decoder needs about a third of ctrl6's steps in a row and
   half of base's, and moves a little less weight than ctrl6. The price: each
   draft pass works on 64 slots where a left-to-right step with a cache works
   on one, so it is faster only if the NPU has spare compute (the plan's
   premise), and no NPU engine exists yet to time it. The quality it costs:
   nothing on plain, decoy and the held-out worlds pooled; about 7 points on
   cluttered rows; and on seen worlds 14-19 points against ctrl6 and 9-15
   against base (means of seeds).

## What this means

- Per the plan's gate: the draft adds nothing a deeper left-to-right decoder
  doesn't on accuracy, so the staged line would stop here. ctrl6 (6 layers)
  is the best or tied-best arm on test, decoy, flip and cluttered.
- The gate did not count speed (point 9). On plain and the held-out worlds
  the staged decoder matches left to right at a third of the steps in a row; the seen-world
  loss has a known cause (point 3) and an untried fix, cross-fitted drafts.
  If that fix closes the seen-world gap, the speed comes free. That makes one
  more staged run (about $3-4) worth it; without it, keep left to right.
- Experts (step 3) were designed for the staged decoder. They could sit on
  left to right instead, but D3 removed their strongest motive (forgetting),
  and the router question is trivial for today's three types. The natural
  time to revisit them is the first real bolt-on (report or scheduling).

### Recipe and deviations from the plan

- R10's recipe: left-to-right training, 12 epochs, batch 64, PAD weight 0.5,
  packed rows, width 256. No reader: the owner removed Ternlight
  (2026-10-02). The encoder is today's, trained with each arm.
- Staged arms train the draft (all 64 slots, from a blank canvas, PAD slots
  at weight 0.5) and the refiner (left to right, reading the draft as extra
  context rows: slot embedding + position + confidence) together, with 10%
  of draft slots randomized for the refiner (5% plus 25% same-kind swaps in
  DRx). The plan's frozen-draft training (`--stage-train`) was not built.
- The router ran after step 2, on step 2's trained encoders, not before.
- DRx was added after the first results showed the copying.
- D3 = the old corpus plus all 9,034 new rows: 36,000 training rows
  (data 28,935, observe-act 5,385, pages 1,680).
- Cost: about $6 against the plan's $3: 14 runs instead of 10, and staged
  runs took about 93 minutes each.
