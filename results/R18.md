# R18: what S6's rows break, looked at from inside the planner

**Date:** 2026-09-27. **Branch:** `description-reading`. **Spend:** $0; laptop
only, on R14–R17's checkpoints.
**Picks up:** R17's untested hypothesis, at the owner's request to dig
deeper before spending on the option split.

## The result

1. **R17's hypothesis was wrong.** R17 guessed that the plain planner picks
   tools by their type labels and that S6's rows teach it to stop. It does not
   pick by type labels. It picks by the description.
2. **What S6's rows break is choosing between two tools of the same shape.**
   Accuracy at those choices falls from 89% to 56% with a quarter of S6's
   rows. Choices where only one tool has the needed shape barely move, from
   96% to 93%.
3. **The damaged planner is not unsure; it is confidently wrong.** It has no
   bias toward the first or last tool in the list. It does lean toward the
   parent thing (the advertiser rather than the ad spot). About a third of its
   wrong picks go to one of the generic helper tools that belong to no thing
   at all.
4. **R16's "SPt loses to A0" was almost all one kind of task.** 15% of the
   exam's tasks give every tool a meaningless name. On tasks with real names,
   SPt is level with A0: 77.2% against 79.3% and 77.8%. On the meaningless-name
   tasks it falls to 52.0%. SPt leans on tool names, because it never saw a
   meaningless name in training. S6's rows, 15% of which have meaningless
   names, cure that.

## Terms

- **A0:** the plain planner. **SPt:** the planner with R12's reading stages,
  which scores each tool three ways (type labels, description, name) and
  weighs the three.
- **A tool's wording:** its name and its one-line description.
- **A tool's type labels:** what it takes and returns, for example "takes a
  spot id, returns a spot".
- **A lookalike pair:** two tools of the same shape for two different things,
  such as "fetch one spot" and "fetch one advertiser". They differ only in
  wording and in the thing named in their type labels. R15's "same-shape swap"
  is calling the wrong one of such a pair.
- **S6 share:** the share of training rows taken from S6 (R17's mixes), with
  the rest from the options-off rows.
- **Teacher-forced:** the correct program is fed in up to the choice being
  measured, so every model is asked the same question at the same point.

## 1. Which clue does the planner follow?

`results/logs/cue_conflict_r18.py` → `cue_conflict_r18.log`.

The probe covers 800 plain-exam tasks, which give 1,000 lookalike choices.
The inputs are rebuilt and checked against every cache's own tensors (50 of
50 match per cache). At each choice it reads which tool the planner picks,
under five versions of the task:

- the task as it is
- the two tools' names and descriptions swapped
- names only swapped
- descriptions only swapped
- the thing-words ("spot", "advertiser") blanked to "item" in both tools'
  wording

The type labels never move. After a swap, the tool with the right type labels
carries the wrong wording, so picking it means following the type labels.

| model | right, as is | follows wording after full swap | follows description after description swap | still right after name swap | still right with thing-words blanked |
|---|---|---|---|---|---|
| A0, 0% S6, seed 0 | 89.5% | 83.7% | 79.5% | 86.9% | 85.1% |
| A0, 0% S6, seed 1 | 89.0% | 78.5% | 73.9% | 85.2% | 86.8% |
| A0, 25% S6 | 55.3% | 47.5% | 45.3% | 50.2% | 50.1% |
| A0, 100% S6 (R13) | 42.8% | 41.1% | 42.3% | 43.5% | 30.6% |
| SPt, 0% S6 | 87.7% | 82.2% | 42.7% | 50.3% | 63.2% |
| SPt, 25% S6 | 64.7% | 60.3% | 43.2% | 49.0% | 40.4% |

- **The no-S6 plain planner goes by the description.**
  - Swapping descriptions sends it to the wrong tool 80% of the time.
  - Swapping names barely matters: it stays right 87% of the time.
  - When the type labels disagree with the wording, the labels lose.
- **But not by the thing-word.** Blanking "spot" and "advertiser" costs it
  only about 4 points. It keys on the rest of each description ("record"
  against "account", "on the traffic log").
- **SPt with no S6 rows uses both name and description.** Either swap alone
  halves its accuracy.
- **S6's rows shift SPt's weighting.** Its weight on the type-label score
  rises from 0.64 to 0.84, and its weight on the name score falls from 0.34
  to 0.11.
- **Neither clue takes over after S6 rows.** With 25% S6 the plain planner
  follows the swapped wording less often, and the type labels do not take
  over.

## 2. Lookalike choices break; shape-unique choices do not

`results/logs/tool_choice_r18.py` → `tool_choice_r18.log`: every tool choice
in 800 teacher-forced plain-exam tasks, with the pick limited to the task's
tools as decoding limits it.

| model | lookalike choices | shape-unique choices |
|---|---|---|
| A0, S5 rows | 86.8% | 96.9% |
| A0, 0% S6, seed 0 / seed 1 | 89.2% / 89.0% | 96.4% / 95.2% |
| **A0, 25% S6** | **55.8%** | 93.4% |
| **A0, 100% S6** | **43.6%** | 92.4% |
| SPt, 0% S6 | 87.8% | 93.1% |
| SPt, 25% / 50% / 100% S6 | 64.8% / 61.4% / 56.3% | 95.6% / 95.9% / 96.1% |

S6's rows cost the plain planner 33 points on lookalike choices and 3 on the
rest. This is R17's plain-exam cost, located.

## 3. How the damaged planner goes wrong

- **Confident, not unsure** (from `cue_conflict_r18.json`):
  - Only 7–13% of lookalike choices fall between 20% and 80% probability, for
    every model.
  - When an S6-trained planner is wrong, the right tool got 4–6% on
    average.
  - It is not spreading its bet.
- **No position bias** (`pair_lean_r18.log`): when the pick is one of the
  pair, it is the earlier-listed tool 50–53% of the time, for every model.
- **A lean toward the parent thing.** The parent is the one the other's
  fields point at: `spot.advertiser` makes the advertiser the parent. Among
  picks within the pair:

  | model | picks the parent | parent is right |
  |---|---|---|
  | A0, 0% S6 | 33% | 27% |
  | SPt, 25% S6 | 45% | 31% |
  | A0, 25% S6 | 50% | 28% |
  | A0, 100% S6 | 58% | 29% |

  This matches R15, where swaps went child to parent almost every time.
- **A third of the wrong picks are generic tools** (`tool_choice_r18.log`):
  - The wrong picks go to the lookalike (47–55%) or to a generic helper that
    belongs to no thing (31–34%). The helpers are "write a short message",
    "look up the help docs", "sum a list".
  - The no-S6 planner almost never does this: 0% and 15% for its two seeds.

## 4. SPt and meaningless names

`results/logs/names_gap_r18.py` → `names_gap_r18.log`.

| model | tasks with real names | tasks with meaningless names |
|---|---|---|
| A0, 0% S6, seed 0 / seed 1 | 79.3% / 77.8% | 80.1% / 74.7% |
| **SPt, 0% S6** | **77.2%** | **52.0%** |
| SPt, 25% / 50% / 100% S6 | 62.3% / 60.6% / 56.8% | 59.1% / 57.1% / 52.6% |
| A0, 25% / 100% S6 | 54.2% / 45.3% | 54.8% / 48.3% |

- **SPt without S6 rows is as good as A0 on real-name tasks.** Its R16
  shortfall is the meaningless-name tasks.
- **A0 does not depend on names at all.** So names cannot explain A0's
  collapse after S6 rows.
- **For the tasks we care about, SPt on options-off rows needs one thing.**
  It needs some training rows with meaningless names, but without the rest of
  S6.

## What is ruled out, and what is left

**Ruled out as the cause of A0's collapse:**

- **The planner stopped using type labels.** It never used them.
- **It stopped using names.** A0 never needed names.
- **It stopped reading the thing-word in descriptions.** It never depended on
  it.
- **It is hedging between lookalikes.** It is confident.
- **A list-position habit.** There is none.

**Left:** S6's rows make descriptions stop deciding between lookalike tools,
and the planner falls back on a lean toward the parent thing and toward
generic helper tools. Which of S6's three options does this is still not
known.

Two readings fit:

- **Decoys** are the lead. Every decoy shares its tool's shape and differs only
  in subtle wording, so a planner that cannot learn that subtle wording may
  learn that wording does not settle same-shape choices at all.
- **Opaque names** could also be responsible, in some way the probes have not
  yet shown.

## Next

1. **The option split at 25%, as R17 proposed.** Three arms, each on 25% of
   rows with the rest options-off:
   - decoys only
   - decoys with twin roles
   - meaningless names only

   `results/logs/tool_choice_r18.py` then shows directly which arm breaks
   lookalike choices. The pod run is about $0.80; the laptop generation takes
   about an hour per arm. It needs a go-ahead.
2. **Cheap and likely useful whatever the split shows:** SPt on options-off
   rows plus meaningless names only. By finding 4, that should close SPt's
   25-point gap on meaningless-name tasks without S6's lookalike damage. It
   is the same run as arm 3 with SPt instead of A0.
