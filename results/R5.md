**Date:** 2026-09-08. **Plan:** `.claude/plans/spec-0.4.0.md` §5 (step 0).
**Model:** Qwen3.8-27B UD-IQ3_S, untuned, in-context, per-task grammar,

(7 E-known, 10 demo, 8 crowded), re-rendered under each surface by

## 2. What each lever did

**MOST recovers the argmax tasks (plan 0b: decided).** With think, both
"the user with the most overdue cards" tasks (`kanban_L4`, `crm_L4`) pass
in all three stdlib-bearing arms, and every one of those six programs
uses `MOST`:

```
CALL T8 -> r0
FILTER r0 F20 LT C0 -> r1
MOST r1 F4 -> r2
CALL T4 r2 -> r3
CALL T6 r3.F16 C1
STOP
```

Under R4's think arm the same model declared both tasks `UNSUPPORTED`.
Without think it finds `MOST` once (kinds arm, `crm_L4`, passes); the
no-think `kanban_L4` pass in the stdlib arm is a different program (sort by
due, take the first card's assignee) that happens to name the right user.
`LEAST` was never needed on this slice.

**EMPTY is the branch the model wanted.** On `demo_10_s4` and `demo_10_s1`
— the two tasks where R4's PAUSE paragraph had induced `IF r1 EQ C6`, a
list compared to a bool — every 0.4.0 arm writes `IF EMPTY r1` and passes.
Its misuses are shape errors the corpus can teach: `IF NOT EMPTY r0` before
`r0` is bound (`UNBOUND`, twice in the no-think stdlib arm).

**Typed letters buy compile, not goal (plan 0a: the surface carries binding
information, and that is all it carries).** Compile 18 → 22 without think,
24 → 25 with. The four static errors that vanish come back as programs
that compile and are wrong: `crm_L4` messages every customer, `demo_11_s2`
duplicates the card without the "Copy of" template, `demo_12_s1` acts
instead of declining Cyrus. Total goal is unchanged at 17. **Compile rate
is not the metric; the letters remove the checker's ability to catch a
semantic miss as a type error.** The two type errors that survive are a
name slot fed an id (`FILTER r0 F144 EQ I0`, `comic_publisher`) and an
abort with the wrong referent kind (`ABORT NEEDS_INFO S0`).

**Kinds and schema enums: +1 with think, and two enum-induced misses.**
`winery_L10` flips to pass under kinds (the enum constant it needed). The
two tasks left at 23/25 are both the schema enums giving the model a
legal wrong path: `golf_club_L10` sets `status = "cancelled"` through
`set_status` instead of calling `cancel_tee_time`, and `driving_school_L9`
("clean up the lesson schedule", one constant: the no_show stage) sees
`booked` and `completed` beside it and declares `AMBIGUOUS`. Emitting every
enum value for every touched entity is a cost as well as a gain; the
130-task confirmation (§3) is what decides whether it nets positive.

## 4. What this settles for S4

- `MOST`/`LEAST` and `EMPTY` stay: a capable model reaches for them
  unprompted and they close the two failure classes they were named for.
- Typed letters are a corpus decision, not a decoding one: they make
  binding legible (compile 25/25 with think) and the small model has to
  learn the semantics that the checker no longer polices. That is exactly
  the claim-2 measurement in `typed-symbols.md` §3, and only the retrain
  answers it.
- Schema enums: emit them, but the tool that owns the transition should
  win over a status write. That is a generator/description question
  (`golf_club`), and a wording question for one-constant cleanup requests.
