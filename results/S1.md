# S1 — Multi-domain + crowded-context retrain (0.8B)

**Ran:** 2026-09-01 · plan: `.claude/plans/ship-model-track.md` · eval CPU,
llama.cpp, unconstrained decoding, Q8_0, ctx 16384 (crowded/OOD) or 4096
(known) — same harness as S0.

**Change from S0's 0.8B-B baseline:** same model size, same SFT recipe.
Training corpus regenerated across ~100+ sampled domains (41 reserved
domains held out, never trained on) plus a ~30% crowded-context slice
(`--crowd 15:60`) per the S0 amendment. Nothing else moved.

## Result

| Suite | S0 0.8B-B | S1 0.8B | Δ | compile_ok (S1) |
|---|---|---|---|---|
| E-known (1000, in-distribution) | 98.5% | **97.8%** | −0.7 | 99.7% |
| E-foreign (500, unseen domains) | 63.4% | **97.0%** | **+33.6** | 99.8% |
| E-crowded (300, 38–78 tools) | 23.7% | **94.7%** | **+71.0** | 98.3% |
| E-ood-english (200, restyled) | 63.0%* | **92.5%** | +29.5* | 98.5% |

\* S0's E-ood number was paired against the same 200 E-foreign tasks under
5 rewritten phrasings; S1's E-ood run is the same restyled suite, scored
independently rather than paired. Directionally comparable, not exact.

**S1 pass gate (from the plan): E-foreign improves materially, E-known
regression ≤1 point. Both met** — E-foreign +33.6, E-known −0.7.

## By level (goal_success)

Every suite: L0–L8 sit at 90–100%, L10 (multi-segment PAUSE/continue) is
clean at 100% on all four suites. The one soft spot is consistent across
every suite: **L9 (ambiguous scope)**.

| Suite | L9 |
|---|---|
| E-known | 48/48 (100%) |
| E-foreign | 16/24 (67%) |
| E-crowded | 7/14 (50%) |
| E-ood | 7/9 (78%) |

L9 is in-distribution-solved but generalizes worst — consistent with S0's
finding #3 that ambiguous scope is a PAUSE-and-confirm product mechanism,
not something to keep chasing with more data at this size.

E-crowded's other soft spot, L3 (33/35), and E-ood's L3 (15/20) are noise
at these n; nothing else drops below 90%.

## What this settles

S0 predicted the crowded slice would move E-crowded "off the floor toward
E-foreign's level" — it did better than that: crowded and foreign now
score within 2.3 points of each other. **Tool selection at scale was a
data-diversity gap, not a capacity ceiling** — training on distractor-laden
contexts fixed it in one retrain, no architecture change.

**Answer to the original question — can we ship without customers
retraining on their own tools:** yes, at 0.8B. The ship gate
(`.claude/plans/ship-model-track.md` §S5: ≥97% E-known, ≥94% E-foreign,
≥90% E-crowded) is met on every accuracy line:

| Gate | Target | S1 0.8B |
|---|---|---|
| E-known | ≥97% | 97.8% ✓ |
| E-foreign | ≥94% | 97.0% ✓ |
| E-crowded | ≥90% | 94.7% ✓ |

Remaining ship-gate dimensions (≤300M params, imatrix-Q4_K_M ≤~200MB) are
untouched by S1 — that's the Z-ladder (S2 vocab prune → S3 tokenizer
surgery → S4 depth prune), still ahead. S1 is the accuracy floor the
ladder now has to hold onto while shrinking.

## Cost

Corpus regeneration + retrain: ~$5 GPU (RunPod 4090, per plan estimate).
Eval: local CPU, ~4.5 hours wall-clock (crowded 14s/task × 300, known
4.5s/task × 1000, ood 5s/task × 200) — no GPU billing.

## Note: a real bug in the eval harness, fixed here

`baselines/qwen/run_a.py` defaulted to `--ctx 4096`. E-crowded prompts run
up to ~9,700 input tokens (30–80 tool schemas in context); the first S1
crowded eval run crashed (`llama_cpp.ValueError: Requested tokens (4131)
exceed context window of 4096`) on task 1. Fixed by passing `--ctx 16384`
explicitly for E-crowded and E-ood-english (both use `--domains`, both
carry large tool contexts); E-known stays on the 4096 default (max
observed ~1,150 tokens). Worth promoting to a real default/derived value
in `run_a.py` before the Z-ladder runs reuse this script.

## Note: grammar-on column for E-ood-english (2026-09-01, after the gbnf fix)

Every S0/S1 number above is unconstrained decoding. The kanban-ui demo
decodes with `baselines/qwen/agent_core.gbnf`, and that grammar had a
terminator bug (mandatory newline after `STOP` masked EOG for a model
trained on stripped targets — see `results/R2.md` Condition B finding 2
and `.claude/plans/grammar-terminator-newline.md`). After the fix, the S1
checkpoint was rerun on E-ood-english with the grammar on
(`results/s1_0.8b_q8_ood_grammar.jsonl`):

| E-ood-english (200) | parse | compile | goal | UNREACHABLE rows |
|---|---|---|---|---|
| unconstrained | 100% | 98.5% | 92.5% | 1 |
| grammar (fixed) | 100% | 98.5% | 92.5% | 0 |

Task-for-task identical goal outcomes. The three static failures differ
in kind only: the unconstrained arm's `UNREACHABLE` diagnostics become
`UNBOUND` under the grammar (the same wrong programs, no longer able to
ramble past a terminator). The grammar is a no-op on accuracy for this
checkpoint on this suite, so the demo's grammar-on decoding is now
represented by the unconstrained numbers above.
