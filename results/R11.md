# R11 — an exam a style reader cannot pass, and a split encoder to take it

**Date:** 2026-09-23/24 (unattended run of `.claude/plans/description-reading.md`
v4, steps 1–6). **Branch:** `description-reading`. **Follows:** `results/R10.md`
§8–§9, which found the decoyed exam passable without reading the request.

**Summary.** Step 1 built an exam a style reader cannot pass, but only on the
four slots where every twin can be the working answer. On those decisions all
audit gates hold (AUC 0.48–0.52). Elsewhere the real tool is the one requests
always ask for, so those decisions cannot measure reading (§1). Step 2 built the
split encoder with spec 0.8.0, bit-identical with its flags off, and found that
R9 and R10 ran with no tool→field graph edges (§2a). Step 3 got a 128-wide
description stage from chance to **87.8%** on the reading decisions, against
the 33M teacher's **89.9%**. **The gate is missed by 2.1 points,** so
steps 4 and 6 (the pod) did not run and nothing was spent (§3). Step 5's laptop
half says the stages ship at 4-bit for free (§5).

---

## 1. Step 1 — the exam

### 1a. What was built

- **Authored decoys.** Every theme pack (all 143, the 42 reserved exam worlds
  included) now carries 3 decoys per tool on its nine tool slots, each a name
  and a description in the theme's own `desc_style` and naming style
  (`data/gen/THEME_SCHEMA.md` "Decoys"). It also authors its nine generic tools
  (create, the four note tools, image, writer, search, set-image) in the same
  voice: before this, those tools had one template description in every world.
  12 parallel authoring passes: 7,722 decoys plus 1,287 generic-tool lines,
  and many real names and descriptions re-worded to match their siblings.
  `--check` passes for every file, the full 143-theme smoke passes, and no
  theme carries another theme's decoys (a vocabulary cross-check).
- **The audit** (`harness/decoy_audit.py`): the classifier from R10 §8,
  promoted to a gate. Given one tool's text and no request, can a
  classifier tell real from decoy? Fitted on half the worlds and scored on the
  other half, averaged over 5 halvings; also fitted on the training worlds and
  scored on the exam's. Four readers: description bag-of-words (words, case,
  bigrams, punctuation, length), name bag-of-words (parts, character trigrams,
  case style), the teacher's embeddings, and the one-token word share under
  the cache tokenizer. Gate: every AUC ≤ 0.60, one-token share within 2 points.
- **Opaque names** (`--opaque-names 0.15`): on 15% of rows *every* tool, real
  and decoy alike, is renamed `op_621`, `job_451`… The old per-decoy nonsense
  names only ever landed on decoys, which made "has a nonsense name" a decoy
  tell. 79/79 opaque rows replay to goal (a renaming consistency check).
- **Uniform twin roles** (`--twin-roles`, below) and the **flip probe**
  (`data/gen/flip_probe.py`, 400 rows whose answer is always a sibling the
  theme did not author as the tool).

### 1b. The audit, three times

| exam | description | name | teacher | train → exam (desc / name / teacher) | one-token real vs decoy |
|---|---|---|---|---|---|
| R10's (bank decoys) | **1.000** | 0.996 | 0.997 | — | 85.9% vs 73.9% |
| pilot, 4 themes authored | 0.753 | 0.902 | 0.764 | — | 84.2% vs 73.5% |
| all 143 authored, "same granularity" rule | 0.800 | 0.709 | 0.723 | 0.834 / 0.761 / 0.756 | 78.2% vs 73.9% |
| **flip slots, uniform roles** | **0.519** | **0.483** | **0.510** | **0.511 / 0.505 / 0.508** | **73.9% vs 73.7%** |

Every gate holds on the last row, and it is the only row where any does.

**Why authoring alone could not pass.** The pilot's decoys were
specialisations of a generic real tool (`listOverdueReviews` beside
`listSubmissions`), and "narrower" is a feature. The revision rule, "change
*what*, never *how much*", with the real line re-worded to match, took
names from 0.90 to 0.71. Descriptions stayed at 0.80, and the per-slot
breakdown shows where:

| slot | description AUC |
|---|---|
| delete_child / set_bool / set_ref / send (flip slots) | 0.46 / 0.44 / 0.53 / 0.48 |
| list_child / list_parent / create | 0.72 / 0.75 / 0.63 |
| get_child / get_parent / set_enum | 0.84 / 0.89 / 0.82 |
| the note tools, image, writer, search, set-image | 0.89–0.98 |

On the non-flip slots, in every world, the real tool is the one requests ask
for. The recipes that use a note tool say "add a note", so the real note tool
says "note" and its siblings say "reply", "pin", "redact". A classifier learns
"note" as real across worlds. Its reason is also a reading model's reason, so
these decisions are not evidence of a shortcut. They are *uninformative*:
reading and style give the same answer, and a correct pick shows nothing about
which one the model used. No authoring can fix that while the request always
names the canonical action.

**Why the flip slots pass.** On delete / flag / re-parent / send, the request
is written from the tool's own templates ("void the fares on segment X"). So
the working tool can be any sibling, provided the request is written with
*its* templates. `--twin-roles` draws it uniformly per row, from the authored
tool and its three siblings. The sandbox impl moves with it, so goal checks
stay consistent. A row whose recipe has fixed wording for the slot (the vague
L9 requests, the fallback "let {name} know") is resampled rather than taught
(`domains.request_fits`). Across a corpus no sibling's text is likelier to be
the answer than another's, and the audit sees exactly that.

This is the fallback the plan named ("twins that each work and can each be
the answer"), applied where it can be. The decoys on the other slots stay in
the corpus as distractors, and every grounding number below is quoted on
**flip-slot decisions** (`provenance.flip_slot_tools`, cache column
`flip_tool`, `decoy_audit --flip-only`).

## 2. Step 2 — the split encoder

Built and committed (911b578) with the spec amendment in the same commit
(spec 0.8.0: a tool's declared name is input text, never a symbol).

- Flags off: the forward pass is **bit-identical** to the committed model on
  the R10 cache (a seeded model built from HEAD's `model.py` and from the new
  one, same batch, `torch.equal`).
- Packed vs padded: equal under 1e-5 on real rows through the real input path,
  once the bug below was fixed (`test_stages.py`).

### 2a. A bug found by the packing check: R9 and R10 had no tool→field graph

`prep.py` built the schema graph's edges in compact indices (field *j* at
`n_tool + j`), then wrote them into a tensor laid out with fields at
`max_tool + j`. That is right only when a task has exactly `max_tool` tools.
It held through R8 (18 tools, `max_tool` 18). In R9's cache (training rows of
14–18 tools, `max_tool` 50, widened by the decoyed holdout) and R10's (22 tools
since the compute block, `max_tool` 54) it held on **0 of 25,711 and 0 of
27,000** training rows. (The 2026-09-23 commit message says "50 and 82"; 82 is
R10's tool + field row count, and its `max_tool` is 54.) Every tool's edges to its fields landed on *padded tool rows*,
and every field's edges to its entity mates landed on tool rows. **The graph
pass of R9 and R10 connected no tool to any field.** Each tool attended to
itself and to a few all-padding vectors. Field symbols still reached the tool
through its own line text (`=F12`) and the turn encoder, which is presumably
why nothing looked broken.

Found because a packed run zeroes padded rows and the logits moved by 2.5e-2
where they should not move at all. Fixed in `prep.layout_edges`, with a test
that no live line reads a padded one. Caches built before 2026-09-23 keep the
old edges, since the adjacency is stored in the cache: R9/R10 reproduce as
run, and their numbers are numbers for a model without a working graph pass.

## 3. Step 3 — the stages on their own

**Decision rule, written before the final numbers:** the plan's gate is "the
pretrained description + name stages, gated, pick the real twin at least as
often as the teacher does zero-shot on descriptions". It is graded on
**readable flip-slot decisions**, the population §1b established as the only
one that measures reading, against the teacher's pick on those same
decisions. A flip-slot call is readable when its request carries the called
tool's own templates (`stage_pretrain.readable`); 14% of S6's are not, see
below. All-decision numbers are reported and do not decide. The best step-3
arm is the one graded. If it fails, step 4 does not run (the condition set
with the owner before this run).

**The arms** (`stage_pretrain.py` on `data_cache_s6`, laptop CPU, name stage
128×2 throughout; graded mid-run on the first 2,000 decoyed and flip exam
rows, 861 readable flip-slot decisions):

| arm | description stage | pooling | token init | relational weight | flip-slot twin weight | open pairs | epochs | flip-slot decisions | all twin decisions | dims used |
|---|---|---|---|---|---|---|---|---|---|---|
| X0 | 128×4 | summary token | random | 1 | 0 | no | 0.6 | 46.2% | 67.7% | 2.3 |
| — | 128×4 | summary token | teacher | 1 | 0 | no | 0.3 | 41.5% | 65.5% | 2.1 |
| X2 | 128×4 | summary token | teacher | 20 | 3 | no | 0.3 | 41.7% | 64.8% | 3.2 |
| X1 | 128×4 | **mean** | teacher | **20** | 0 | no | 1 | 72.4% | 78.0% | 12.4 |
| X4 | 128×4 | mean | teacher | 20 | **3** | no | 3 | **88.5%** | 82.5% | 14.7 |
| X5 | 256×4 | mean | teacher | 20 | 3 | **yes** | 2 | 88.0% | 81.8% | 15.9 |
| X6 | 128×4 | mean | teacher | 20 | 3 | yes | 3 | 87.7% | 81.6% | 15.3 |
| teacher (bge-small, zero-shot, descriptions) | | | | | | | | **88.9%** | 61.9% | |
| chance (uniform inside the twin group) | | | | | | | | 41.3% | 41.8% | |

(X3, mean + flip weight at 1 epoch, was stopped at step 250 in favour of X4.
It read 55.3% there, against X1's 50.6% at the same step.)

**What moved it.** Three things, in order of size:

1. **Mean pooling instead of a summary token.** Every summary-token arm
   stayed at chance on flip slots however long it trained, while scoring
   65% on all twin decisions. It learned the canonical-tool pattern (§1b)
   and never matched words. Mean pooling keeps each token's contribution in
   the vector, and flip decisions left chance within 250 steps.
2. **A relational loss that is not negligible.** The MSE between the
   stage's and the teacher's cosine matrices is around 0.02–0.05, so at
   weight 1 it added nothing next to a contrastive loss of about 2.
   At 20 it carries the teacher's geometry. Participation ratio went from
   1.6–3 dimensions to 12–15.
3. **Twins first on flip slots**, as a separate term. Flip decisions are a
   third of the calls, and the easy twin groups drown them out otherwise.

Two losses as first written were wrong. The first contrastive loss was
`-log(Σ_pos / Σ_all)`, which is satisfied as soon as *any* called tool scores
high. Every row calls an easy list tool, so the action tool never had to beat
its twins. It is now per-positive InfoNCE. The first evaluation also graded
the plain half of the exam, which has no twins.

**The gate, graded on the whole exam** (4,859 decoyed and flip rows; 8,147
twin decisions, 2,309 of them readable flip-slot ones):

| | flip-slot decisions | all twin decisions | opaque-name rows (all twin decisions) |
|---|---|---|---|
| X4 stages (desc + name, gated) | **87.8%** | 82.1% | 76.6% |
| X6 stages (X4 + open pairs) | 87.0% | 80.1% | 74.1% |
| X5 stages (256 wide + open pairs) | 85.8% | 81.2% | 75.6% |
| X4 description stage alone | 84.9% | 81.2% | 76.9% |
| X4 name stage alone | 74.7% | 69.3% | — |
| teacher, descriptions | **89.9%** | 62.8% | — |
| teacher, names | 78.1% | 61.4% | — |
| chance | 41.4% | 41.7% | — |

**The gate is not met.** The best arm, X4, is **2.1 points short** of the
teacher on the decisions that measure reading (about ±0.7 at this n), and 19
points *ahead* of it on all twin decisions. That lead is §1b's canonical-tool
pattern, which the teacher, never trained here, cannot exploit. The other two
finished recipes land further short. Per the condition set before the run,
**step 4 does not run, and step 6, which works on step 4's winner, does not
either.**

**What it answers.** The plan asked this step to be "the cheapest test of
'is the model too small?'": if a ~3M description stage cannot reach a 33M
encoder's zero-shot number, capacity is implicated. Read literally, it is
implicated, narrowly. What the arms add:

- **Width is not the lever.** Doubling the description stage to 256 wide
  (X5, with open pairs) *lost* two points against the 128-wide X4 (85.8% vs
  87.8%, full exam). That is the direction R10 §9b predicted: the twin
  distinction is low-dimensional, and the stages use about 15 dimensions.
- **Open pairs do not help** (X6 87.0% vs X4 87.8%, same recipe
  otherwise). The 6,893 request/tool-name pairs are a different register
  from the themed corpus, and the teacher already carries general language.
- **The recipe is most of it.** The same 128×4 stage goes from chance (a
  summary token) to 87.8% by changing pooling, the relational weight and
  the twins-first term. It reads well above a word-overlap reader on the
  same decisions (78.0%) and at 4-bit costs nothing.
- **Still open:** data. X4 was still rising at its last evaluations
  (86.3 → 88.0 → 88.5% on the subset over the final third). The 14% of S6's
  training flip calls whose request never names the tool are noise the
  current generator removes. Neither was tried here: both need a
  regenerated corpus.

Other readings from X4: the gate puts 0.81 of its weight on the description
stage on opaque-name rows and 0.57 on named rows, which is the behaviour
§3 of the plan asked for. 4-bit rounding costs nothing on the full exam
(87.8% at fp32, int8 and u4 alike).

The 14% of S6's flip-slot calls whose request never names the tool (§1c) are
in the training data and excluded from grading. The generator now rejects
them (7c3e765); S6 predates that.

### 3b. Closing the gap (2026-09-24, after the run)

§7 item 2 as written (regenerate S6 with the current generator, retrain for
longer) could not run: the generator could no longer produce level 9 or most
of level 12. What ran instead, and what it found.

**Why regeneration failed.** 7c3e765 made the generator reject any row
whose request does not carry the called flip-slot tool's own wording, the
authored tool included. Two recipes have fixed wording by design:

- **Level 9, "ambiguous"**: a deliberately vague request ("Clean up the
  lesson library.") whose program deletes or flags records. Delete and flag
  are flip slots, and the request names neither.
- **Level 12, "format_reminder"**: look up a record, fill in a template,
  send it ("send Dana a reminder that reads …"). Send is a flip slot, and
  "send a reminder" fits notify and email alike.

Every training shard stopped at `FATAL: level 9 failed 25 consecutive
attempts`, 1,701 of 30,000 rows in all (`results/logs/gen_s6b.sh`; its Y1/Y2
arms trained on that and are void). The generator is back to checking
swapped-in siblings only, as before 7c3e765 (`data/gen/__main__.py`).

**The fix used instead: a training mask.** `stage_pretrain.py
--drop-unreadable` leaves out of every contrastive term (as both a right and
a wrong answer) each called flip-slot tool whose request never names it, using
the same `readable` test the exam's grading already applies. On S6's training
split that is 2,985 of 14,742 called flip-slot tools (20%): level 9 1,037
rows, level 12 1,116, the rest from levels 4, 7, 15, 17, 19. All 2,985 have
the authored tool as the answer, so they taught exactly the "authored tool
wins" default the exam is built to catch. The relational loss keeps them;
it carries the teacher's geometry, not answers. Off by default, so X4
reproduces.

**The arms** (X4's recipe on the same `data_cache_s6`, full exam, 2,309
readable flip-slot decisions; `results/logs/stages_u.sh`):

| arm | mask | epochs | flip-slot decisions | description stage alone | name stage alone | all twin decisions | gate → description, opaque / named rows | dims used |
|---|---|---|---|---|---|---|---|---|
| X4 | no | 3 | 87.8% | 84.9% | 74.7% | 82.1% | 0.81 / 0.57 | 14.9 |
| U1 | yes | 3 | 88.3% | 85.3% | 74.3% | 80.5% | 0.96 / 0.56 | 14.8 |
| **U2** | yes | **6** | **89.1%** | 86.4% | 78.0% | 80.7% | 0.95 / 0.56 | 17.1 |
| teacher, descriptions | | | **89.9%** | | | 62.8% | | |

- **The mask alone is worth +0.5**, within noise. It changes *how* the
  stage decides more than how often it is right: the gate leans on the
  description stage on 96% of opaque-name rows, against 81%. All-twin
  accuracy drops 1.6 points, which is the authored-default shortcut going
  away, not worse reading.
- **Twice the epochs is worth +0.8 more.** X4's flat final 500 steps were
  the cosine schedule reaching zero, not saturation: U2 was still gaining in
  its last third (88.3 → 89.8 → 89.9% on the subset).
- **The gate is still missed, by 0.8 points**, about one standard error of
  either number (0.65 at this n; a paired test was not run). On the 2,000-row
  subset used mid-run, U2 reads 89.9% against the teacher's 88.9%, a pass.
  Read literally, the pre-set condition (stage ≥ teacher on the full exam)
  is not met. Read as a measurement, a 2.26M-parameter stage trained here
  reads the tool a request means as well as the 33M teacher does zero-shot,
  to within the noise of this exam.

## 4. Step 4 — joined to the planner

**Not run**: step 3's gate is not met (§3). Everything for it is prepared and
tested on the laptop. `run_step4.sh` runs the four arms at step 3's recipe.
`pod_bundle_s6.tar.gz` (222 MB) holds the cache; add the stages with

does not depend on step 3 at all. It is the plan's direct measurement of
whether splitting helps the planner, at about $1 on a community 3090.

## 5. Step 5 — 8-bit vs 4-bit

The laptop half, `stage_quant.py`: the step-3 stages rounded after training.
Every attention and feed-forward matmul goes to the format, token tables to
int8, activations to int8 per token; norms and the gate stay float, the split
`quant.py` applies to the planner. Re-graded on the same 2,000 exam rows
(3,329 twin decisions, 861 of them readable flip-slot ones).

| stages | format | all twin decisions | flip-slot decisions | description only | name only |
|---|---|---|---|---|---|
| X1 (128-wide description, 1 epoch) | fp32 | 78.0% | 72.4% | 78.8% | 66.3% |
| | int8 | 78.0% | 72.4% | 78.7% | 66.3% |
| | **u4** | **77.8%** | **72.0%** | 78.6% | 66.4% |

4-bit costs 0.2 points overall and 0.4 on flip-slot decisions, inside the
plan's one-point tolerance. **The stages need no quantisation-aware training
to ship at 4-bit.** At 4-bit the 128-wide description stage (0.8M layer
parameters) takes 0.4 MB of a 4 MB tile. `stage_pretrain --weights u4`
exists in case a wider stage needs it; nothing here did.

The planner-side half of step 5 (training the planner at those formats on
the pod) waits on step 4.
