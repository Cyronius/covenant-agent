## 1. Step 1 — the exam

### 1a. What was built

- **Authored decoys.** Every theme pack (all 143, the 42 reserved exam worlds
  included) now carries 3 decoys per tool on its nine tool slots, each a name
  and a description in the theme's own `desc_style` and naming style
  (`data/gen/THEME_SCHEMA.md` "Decoys"). It also authors its nine generic tools
  (create, the four note tools, image, writer, search, set-image) in the same
  voice: before this, those tools had one template description in every world.
  12 parallel authoring passes: 7,722 decoys plus 1,287 generic-tool lines,
  and many real names and descriptions re-worded to match their siblings.
  `--check` passes for every file, the full 143-theme smoke passes, and no
  theme carries another theme's decoys (a vocabulary cross-check).
- **The audit** (`harness/decoy_audit.py`): the classifier from R10 §8,
  promoted to a gate. Given one tool's text and no request, can a
  classifier tell real from decoy? Fitted on half the worlds and scored on the
  other half, averaged over 5 halvings; also fitted on the training worlds and
  scored on the exam's. Four readers: description bag-of-words (words, case,
  bigrams, punctuation, length), name bag-of-words (parts, character trigrams,
  case style), the teacher's embeddings, and the one-token word share under
  the cache tokenizer. Gate: every AUC ≤ 0.60, one-token share within 2 points.
- **Opaque names** (`--opaque-names 0.15`): on 15% of rows *every* tool, real
  and decoy alike, is renamed `op_621`, `job_451`… The old per-decoy nonsense
  names only ever landed on decoys, which made "has a nonsense name" a decoy
  tell. 79/79 opaque rows replay to goal (a renaming consistency check).
- **Uniform twin roles** (`--twin-roles`, below) and the **flip probe**
  (`data/gen/flip_probe.py`, 400 rows whose answer is always a sibling the
  theme did not author as the tool).

### 1b. The audit, three times

| exam | description | name | teacher | train → exam (desc / name / teacher) | one-token real vs decoy |
|---|---|---|---|---|---|
| R10's (bank decoys) | **1.000** | 0.996 | 0.997 | — | 85.9% vs 73.9% |
| pilot, 4 themes authored | 0.753 | 0.902 | 0.764 | — | 84.2% vs 73.5% |
| all 143 authored, "same granularity" rule | 0.800 | 0.709 | 0.723 | 0.834 / 0.761 / 0.756 | 78.2% vs 73.9% |
| **flip slots, uniform roles** | **0.519** | **0.483** | **0.510** | **0.511 / 0.505 / 0.508** | **73.9% vs 73.7%** |

Every gate holds on the last row, and it is the only row where any does.

**Why authoring alone could not pass.** The pilot's decoys were
specialisations of a generic real tool (`listOverdueReviews` beside
`listSubmissions`), and "narrower" is a feature. The revision rule, "change
*what*, never *how much*", with the real line re-worded to match, took
names from 0.90 to 0.71. Descriptions stayed at 0.80, and the per-slot
breakdown shows where:

| slot | description AUC |
|---|---|
| delete_child / set_bool / set_ref / send (flip slots) | 0.46 / 0.44 / 0.53 / 0.48 |
| list_child / list_parent / create | 0.72 / 0.75 / 0.63 |
| get_child / get_parent / set_enum | 0.84 / 0.89 / 0.82 |
| the note tools, image, writer, search, set-image | 0.89–0.98 |

On the non-flip slots, in every world, the real tool is the one requests ask
for. The recipes that use a note tool say "add a note", so the real note tool
says "note" and its siblings say "reply", "pin", "redact". A classifier learns
"note" as real across worlds. Its reason is also a reading model's reason, so
these decisions are not evidence of a shortcut. They are *uninformative*:
reading and style give the same answer, and a correct pick shows nothing about
which one the model used. No authoring can fix that while the request always
names the canonical action.

**Why the flip slots pass.** On delete / flag / re-parent / send, the request
is written from the tool's own templates ("void the fares on segment X"). So
the working tool can be any sibling, provided the request is written with
*its* templates. `--twin-roles` draws it uniformly per row, from the authored
tool and its three siblings. The sandbox impl moves with it, so goal checks
stay consistent. A row whose recipe has fixed wording for the slot (the vague
L9 requests, the fallback "let {name} know") is resampled rather than taught
(`domains.request_fits`). Across a corpus no sibling's text is likelier to be
the answer than another's, and the audit sees exactly that.

This is the fallback the plan named ("twins that each work and can each be
the answer"), applied where it can be. The decoys on the other slots stay in
the corpus as distractors, and every grounding number below is quoted on
**flip-slot decisions** (`provenance.flip_slot_tools`, cache column
`flip_tool`, `decoy_audit --flip-only`).

## 2. Step 2 — the split encoder

Built and committed (911b578) with the spec amendment in the same commit
(spec 0.8.0: a tool's declared name is input text, never a symbol).

- Flags off: the forward pass is **bit-identical** to the committed model on
  the R10 cache (a seeded model built from HEAD's `model.py` and from the new
  one, same batch, `torch.equal`).
- Packed vs padded: equal under 1e-5 on real rows through the real input path,
  once the bug below was fixed (`test_stages.py`).

### 2a. A bug found by the packing check: R9 and R10 had no tool→field graph

`prep.py` built the schema graph's edges in compact indices (field *j* at
`n_tool + j`), then wrote them into a tensor laid out with fields at
`max_tool + j`. That is right only when a task has exactly `max_tool` tools.
It held through R8 (18 tools, `max_tool` 18). Since the compute block (22 tools
per task) and the decoyed holdouts (`max_tool` 50 in R9, 82 in R10), it has not
held on any row. Every tool's edges to its fields landed on *padded tool rows*,
and every field's edges to its entity mates landed on tool rows. **The graph
pass of R9 and R10 connected no tool to any field.** Each tool attended to
itself and to a few all-padding vectors. Field symbols still reached the tool
through its own line text (`=F12`) and the turn encoder, which is presumably
why nothing looked broken.

Found because a packed run zeroes padded rows and the logits moved by 2.5e-2
where they should not move at all. Fixed in `prep.layout_edges`, with a test
that no live line reads a padded one. Caches built before 2026-09-23 keep the
old edges, since the adjacency is stored in the cache: R9/R10 reproduce as
run, and their numbers are numbers for a model without a working graph pass.
