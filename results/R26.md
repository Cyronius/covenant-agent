# R26: a ternary ELECTRA tags who-does-what; Ternlight reads the tagged words

**Date:** 2026-10-01. **Branch:** `description-reading`. **Spend:** $0 (laptop
CPU). **Plan:** `.claude/plans/electra-slot-reader.md`, steps 0-4 (step 4's
pod run is ready and not run). The owner: "yes, I like this plan".

**Terms.** *Reader*: what turns each text (request, constant, field, tool
description) into vectors for the planner; the planner never sees words.
*Role slots*: a fixed set of vectors per text, one per role: action, object,
destination, source, condition, time, amount, plus the whole text. *Body*:
the reader's transformer layers. *Ternary*: weights of -1, 0 or +1 times one
scale per matrix, 8-bit activations, a 4-bit word table (Ternlight's format).
*Constant probe*: does matching the request's vectors against each constant
score the constants the reference program uses above the ones it doesn't
(pair accuracy, 50 = chance; `chunk_probe.py`).

## The result

1. **The reader now carries who-does-what, as a few vectors per text.** A
   ternary copy of ELECTRA-small marks which words fill each role; the shipped
   Ternlight reads those words. Held-out text, the parser's spans as the
   reference:

   | | ternary reader | (full-precision ELECTRA) |
   |---|---|---|
   | role spans exactly the parser's | 88.3% | 88.2% |
   | role present / absent right | 96.3% | 96.4% |
   | our requests (never trained on), exact / overlap | 68.7% / 0.79 | 74.5% / 0.82 |

   "move it to bob" -> destination *bob*; "move it from bob" -> source *bob*;
   "copy the report from the archive to the inbox" and its swap trade the two
   places; "delete the cards that are not done" -> condition *that are not
   done*. Ternlight alone can't tell any of these apart (R25, C0).

2. **It matches constants as well as Ternlight's 4-word chunks only when the
   chunks stay.** Constant probe (demo / plain / cluttered):

   | | demo | plain | clut |
   |---|---|---|---|
   | Ternlight, 4-word chunks (C0 today) | 84.8 | 66.6 | 87.1 |
   | role slots alone | 79.1 | 63.1 | 84.1 |
   | **role slots + chunks** | 83.8 | **67.7** | **87.6** |
   | the parser's own spans, read by Ternlight (ceiling for slots) | 82.1 | 66.0 | 85.1 |

   So step 4 hands the planner the 7 slots *and* the chunks, and asks whether
   adding roles helps it.

3. **A 12-layer ELECTRA goes ternary with little loss.** Copying full-precision
   ELECTRA word by word and layer by layer (states and attention, as
   TernaryBERT did), 80,000 general-English texts, 75 minutes on the laptop:
   every layer's word states at cosine 0.90-0.95 to full precision, the last
   0.878 (the plan's gate said 0.9). What counts downstream holds: a tagger
   trained on the ternary body tags exactly as well as on full precision (the
   table above).

4. **The reader is 11.4 MB:** the ternary ELECTRA body and tagger
   (`reader/slots/slot_reader.bin`, 6.6 MB, read back bit-exact) and
   Ternlight-mini (4.8 MB). The planner gets 8 vectors for a request, plus
   its chunks.

## How it got there

- **Step 0: ELECTRA carries roles; Ternlight's body can't.** A slot head (one
  learned query per role over the body's word states) trained to copy the
  teacher's vector of each role's words, on 284,000 general-English texts
  parsed by spaCy (`results/logs/slots/check_*.json`):

  | | ELECTRA body | Ternlight body |
  |---|---|---|
  | role routing, held-out (chance ~44%) | 96.0% | 81.3% |
  | role routing, our requests | 93.0% | 75.0% |
  | object <-> destination swapped, right both times (chance 25%) | 81.5% | 0.0% |
  | to -> from, right both times | 88.9% | 27.6% |

- **The slot head that copies vectors matched constants badly** (probe 72.6 /
  57.9 / 73.0): its slots sat at cosine 0.56-0.85 to their targets, close
  enough to tell a sentence's parts apart, too loose to rank constants.
  Ternlight's vectors as targets didn't fix it (72.0 / 56.9 / 72.7). The
  parser's spans read directly by Ternlight did (82.1 / 66.0 / 85.1). So the
  head was replaced by a **tagger**: per role a start and end word or
  "absent" (`slot_tagger.py`), and each slot is Ternlight's vector of the
  tagged words. That is the plan's one design change, recorded in it.
- **A tagger moved between bodies loses roles; retrained, it doesn't.** The
  tagger trained on full-precision ELECTRA, run on the ternary body, lost the
  destination role (exactly right on 15% of the swap-check sentences instead
  of 53%). Retrained on the ternary body (step 2, 28 minutes), it matches
  full precision.
- **What the parser misses, the tagger misses.** "send priya the list" gets no
  destination; "assign Bob to card 6" tags the destination as *card*. The
  tagger copies the parser, so its exact-span rate on swapped sentences is
  40-50% (the swaps are unnatural text, and boundaries count).

## Ready, not run: one pod run

`run_c0s.sh` (bundle `models/tiny/pod_bundle_c0s.tar.gz`, 794 MB; scorer
`results/logs/score_c0s.sh`), six runs on one A40, about 3 hours, about $2:

| arm | the request reaches the planner as | its own words |
|---|---|---|
| `c0_RL`, `c0_RLs1` | C0: Ternlight's 4-word chunks | kept |
| `c0_SC`, `c0_SCs1` | 7 role slots + the chunks (`data_cache_c0sc`) | kept |
| `c0_SCV`, `c0_SCVs1` | 7 role slots + the chunks | dropped: vectors only |

- `c0_SC` vs `c0_RL`: does reading roles help the planner?
- `c0_SCV` vs `c0_SC`: can the request reach it as vectors only?

In our training requests the action slot is filled 94% of the time, object
69%, time 10%, condition 6%, destination 4%, source 2%: most requests are
lookups, so the run tests mostly action / object / condition. It needs a
go-ahead.

## Not done

- **The engine.** Ternlight's WASM engine can't run the ELECTRA body yet:
  it needs the position table, norms after each sublayer, biases on every
  matrix, the 128->256 projection and the tagger. `pack_reader.py` writes and
  reads the format; the engine port is later. The planner pipeline runs the
  reader in PyTorch.
- **Multi-action requests:** one frame of slots per text.
- **The tagger is fp16, 1.6 MB of the 6.6;** it could go ternary.

    python slot_reader.py parse && python slot_reader.py parse --cue --n-train 150000
    python slot_reader.py teacher && python slot_reader.py teacher --target ternlight

    python reader_table.py --cache data_cache_c0sc --ternlight reader
