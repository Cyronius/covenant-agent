## Two inference-time fixes, both on the laptop, $0

**Only a tool after `CALL`.** 58% of SPt's failed plain programs wrote a
register, constant or field where the grammar requires a tool (`CALL r0`,
`CALL S0`; `call = "CALL" tool {operand}`, `spec/agent_core.md:68`), often
with the rest of the program right. `sample.local_mask` now blocks everything
but the task's own tools there. Plain exam: SPt 56.0 → 58.6%, A0 45.9 →
47.1%. Smaller than the 58% suggested: forced to name a tool, the planner
mostly names the wrong one. `CALL r0` was a symptom of not knowing which
tool, not a slip.

**Best of 4.** If the greedy program does not compile, sample up to three
more at temperature 0.7 and keep the first that compiles (`evaluate.py
--best-of`). Plain 58.6 → 60.7%, decoyed 50.3 → 51.7%. Compile rate on the
plain exam is still only 68%, against 99.9% on the test split.

## What is left: the wrong entity's tool

After the decoding fix (`models/tiny/fail_kinds.py`,
`results/logs/planner/fail_kinds_*_plain_mask.json`), **87% of SPt's failed
plain programs start with a tool of another signature** (A0: 89%), the
failure R12 traced in R9: the request names two entities ("email every
shipper that has a non-hazmat shipment") and the planner starts from the
wrong one. R12 put that down to the missing tool → field links; this run has
them and the failure is still there, now the dominant one. The fix did not
solve it, or something else in this setup is making it worse.

What it is not:

- **Not tool names as a crutch.** Spec 0.8.0 put names on the model-facing
  line, and names are world-specific. But SPt reads opaque-name rows at
  54.3% against named rows' 59.5%, and A0 at 48.6% against 46.8%: hiding the
  names barely matters.
- **Not the look-alikes.** Same-signature picks are under 1% of the plain
  failures.

By level (SPt, plain, with the fix): 0, 13, 16, 17, 18 at 91–100%; the
multi-entity levels collapse, 2 (24%), 3 (19%), 4 (19%), 6 (15%), 9 (18%) and
19 (17%), against R9's 39–62% on the same levels.

## What would tell the causes apart (done: see "The two diagnostics" below)

Every candidate changed between R9 and this run at once: the corpus (S5 →
S6: authored decoys on every training row, uniform twin roles, 15%
opaque-name rows, 120-character descriptions), names on the line, R12's
tokenizer, and the schema-graph fix. Two runs separate them, each about $0.30
on the same pod shape:

1. **A0 on R9's corpus, current code** (R11 §7 item 3, never run): if it
   beats R9's 70%, the graph fix works and S6 is what hurts unseen worlds;
   if it matches R9, the fix does nothing for entity choice.
2. **A0 on S6 without names on the line**: the names check above, done
   properly (trained without, not just hidden at test time).

## The two diagnostics (2026-09-26, $0.54)

Both A0 with R10's recipe, one A40, everything pulled back to
`models/tiny/runs/pod_diag/` (checkpoints, generations, logs; sizes checked).
`models/tiny/run_diag.sh`; logs and summaries `results/logs/diag/`.

| model | exam | goal | against |
|---|---|---|---|
| **A0, R10's corpus (S5), current code** | S5 plain (unseen worlds) | **76.9%** | R10, same corpus and exam, old code: 70.7% |
| | S5 decoyed | 36.8% | R10: 42.1% |
| | S5 test (training worlds) | 97.7% | |
| | **S6 plain** (same tasks as above) | **70.4%** | A0 trained on S6: 47.1%; SPt: 58.6% (both with the `CALL` mask) |
| **A0, S6 without names on the line** | S6 plain | 49.2% | A0 on S6 with names: 47.1% |

(The S5 model's exam carried S6's plain half too, ids suffixed `+s6`, in one
cache whose layout matched R10's exactly. The `CALL` mask was on in every
generation here; R9 made that error on ~1% of tasks.)

1. **The S6 training corpus is what hurts unseen worlds, not the S6 exam and
   not names.** A planner trained on S5 reaches 70.4% on the S6 plain exam;
   the same architecture trained on S6 reaches 47%. Removing tool names from
   S6 training moves it 2 points (one seed, inside the noise). Something in
   S6's training data costs 23 points on unseen worlds: every training row
   decoyed (48.8 tools a row against the exam's 21.8), uniform twin roles,
   15% opaque-name rows, 120-character descriptions, authored decoy text.
   Which of these, this run cannot say.
2. **The schema-graph fix is worth about +6 on S5's plain exam** (70.7 →
   76.9%, one seed each; R9's three seeds averaged 70.4). Verified in the
   data: in R10's cache 0% of graph edges joined a live tool to a live field;
   in the rebuilt one 42% do. But it did **not** fix entity choice:
   wrong-entity starts are 15.7% of tasks, the same as R9's 15.8%. The gain
   came from fields (7.2% → 4.6% of tasks) and keywords (3.1% → 1.0%).
   R12's reading of the entity failures as a graph-bug effect was wrong.
3. **The S5 decoyed half fell 5 points** (42.1 → 36.8%). That half is the one
   R10 §8 showed a style reader can pass, so it is a weak measurement either
   way.

**Scoring note.** S5-era tasks cannot be run in today's sandbox: the theme
rewrite for S6 (`a03610e`) renamed tools, so 1,661 of 2,000 S5 plain tasks
and 985 of 1,000 test tasks hit `KeyError: 'get_club'`-style sandbox errors
and read as failures. They were rescored with the scorer and themes from the
commit before it (git worktree `../covenant-pre-a03610e` at `212699a`).
Decoyed rows carry their own sandbox and were unaffected. **Any future S5
score must be taken the same way.**

**The best model for unseen worlds is now the plainest one:** A0 trained on
S5 with the current code, `models/tiny/runs/pod_diag/runs/diag_s5fix/best.pt`
on `data_cache_ho42_fix` (76.9% on S5's plain exam, 70.4% on S6's).
