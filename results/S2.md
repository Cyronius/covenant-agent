## B4 — vocabulary trim (2026-09-02): PASS

**Change:** drop every token the planner never needs from the tokenizer and
the tied embedding, no retraining. Keep-set = tokens used by the S1 corpus
and every eval prompt (7,864) ∪ 256 byte bases ∪ specials ∪ the result
tokens of the first 40,000 BPE merges (a general-English floor, merge rank
≈ pretraining frequency), closed under merge parents so kept tokens stay
reachable. `baselines/qwen/prune_vocab.py`, `baselines/qwen/convert_pruned.py`.

| | tokens | params | Q8_0 GGUF |
|---|---|---|---|
| S1 (Qwen3.5-0.8B tokenizer) | 248,077 | 752M | 812 MB |
| S1 pruned | **42,263** | **541M** | **578 MB** |

**Faithfulness.** Corpus tokenization identical on 6,000 texts. HF fp32
greedy generations identical 6/6. At Q8_0, pruned vs a GGUF re-converted
from the *same* merge: 36/40 prompts identical; all 4 flips at decisions
whose fp32 top-2 margin was 0.07–0.41 logits (median margin on matching
prompts: 7.75), and in one the pruned model picked the fp32 argmax the
unpruned Q8 missed. Q8 itself jitters by that much — two Q8 conversions of
identical weights (shipped S1 vs re-merged) differ by 3/200 on E-ood.

**Suites (grammar on):**

| E-ood-english (200) | goal | compile | gen p50 / p95 |
|---|---|---|---|
| shipped S1 GGUF | 185 | 197 | 8.4 s / 15.2 s |
| re-merged S1 GGUF (same weights, fresh convert) | 188 | 199 | 8.7 s / 15.3 s |
| **pruned** | **185** | **197** | **5.2 s / 8.9 s** |

| demo suite (65) | goal | compile |
|---|---|---|
| re-merged | 21 | 37 |
| pruned | 20 | 35 |

Pruned sits inside the ±3/200 band that two conversions of identical weights
span, and equals the shipped checkpoint exactly on E-ood. **Rung passes**;
the trim rides into the S2 retrain (Lane C).

**The unplanned win is speed.** The output projection over 248k tokens was
a third of the per-token compute at 0.8B; removing it cuts generation
p50 from 8.7 s to 5.2 s and p95 from 15.3 s to 8.9 s on the dev CPU, same
prompts, same grammar. That is before any Z-ladder work.

**Caveat for real requests:** the English floor is 40k merges; a request
using rarer tokens falls back to smaller kept pieces the model never saw
in that segmentation. The real-session eval slice (B1) is the check.

**What fails.** 224 of 234 programs die in the typechecker; 177 on
TYPE_ERROR. The model writes kanban-shaped programs against a world it
has never seen: LIST where OBJ is expected (76), a STR constant where
ID:element / ID:module / ID:course is required (71 / 61 / 45), a module id
where an element id goes (47). The ten that compile call one plausible
tool (update_element, add_sub_item, duplicate_element, rename_module) but
not the one the frontier used, and three of them delete a module.

**Reading.** This is the number the S2 rung rule is measured against:
"e_real_sessions improves" on `route_write_match` and `correct_abstain`,
both 0 today. The failure is not the eval's shape — the world executes
hand-written routes (tests) and the frontier's routes are expressible —
it is that S1 was trained on two small worlds with ≤ 12 tools and short
signatures. Lane C's corpus needs: worlds with 30+ tools and multi-id
signatures (moduleId + columnId), `ABORT AMBIGUOUS` for the 28% of real
turns that are clarifications, the writer/generative tools on the
critical path (46% content-bearing), and the coursebuilder verbs
themselves only through B2 (the world stays held out).


## Lane C — S2 retrain and the S2R real-turn continuation (2026-09-04)

Two models, one rung. **S2** is the planned retrain (50k tasks, v2 surface,
19 levels, 5,348 aborts). **S2R** continues S2's adapter on 900 verified
real turns. The rung fails, but not where it was expected to: the real
suite passes outright and the *synthetic* suites are what block it.

| suite | bar | S1 | S2 | S2R | |
|---|---|---|---|---|---|
| E-known (1000) | ≥97 | 97.8 | 98.2 | **95.3** | S2R miss |
| E-foreign (500) | ≥94 | 97.0 | 97.0 | 96.8 | pass |
| E-crowded (300) | ≥90 | 94.7 | **81.3** | **82.0** | S2 miss, inherited |
| E-ood-english (200) | ≥90 | 92.5 | 94.5 | 95.0 | pass |
| e_demo_requests (65) | — | — | 41.5 | 33.8 | regression |
| e_s2_levels (240) | — | — | 100.0 | 100.0 | — |
| real `route_write_match` | ≥25% | 0 | 0.6% | **50.0%** | pass |
| real `correct_abstain` (73 no-call) | ≥50% | 0 | 0 | **60%** | pass |
| real `unnecessary_destructive` | ≤4 | 4 | 3 | **1** | pass |

### It was never model size

S2 scores **240/240** on a held-out suite at its own seven new levels, on
reserved worlds it never trained on: 60/60 correct abstains, 180/180
correct actions, zero false abstains, all four abort reasons used
(`results/logs/eval_s2_levels.sh`). The same model abstains **0/73** on
real turns. A 0.8B model that could not represent "unsatisfiable request →
ABORT" cannot score 60/60 on it. The capability was present and perfectly
calibrated; the trigger was keyed to generator phrasing.

The whole S2 gradient says the same thing — it does not degrade with task
difficulty, it degrades with distance from the corpus's phrasing:

    e_s2_levels     100%   synthetic, unseen worlds
    e_ood_english    95%   restyled synthetic English
    e_crowded        87%*  synthetic + 60 distractor tools   (*66-row match)
    e_demo_requests  42%   hand-written human requests
    e_real_sessions   1%   real user turns

**900 rows — 1.7% the size of the S2 corpus — moved `route_write_match`
from 0.6% to 50%, and compile from 1.7% to 99.6%.** Vocabulary pruning was
ruled out first: pruned and unpruned S2 score identically on the real
suite (`route_write_match` 0.00625 both, identical status+compile on
118/121 shared tasks).

### What S2R cost, and the two separate failures

**E-crowded is S2's, not S2R's.** S2 lost 13.4 points against S1 (94.7 →
81.3); S2R scores 82.0, statistically the same. On 66 matched tasks the
two models are identical (84.8 each). S1's own writeup called crowding
"a data-diversity gap, not a capacity ceiling" — S2 gave part of that back.
Two candidate causes; one is now measured out. Truncation: rows over the
`--max-len 6144` cap lose their assistant turn under `assistant_only_loss`,
and every one of them is crowded — but there are only **90 of 53,849
(0.17%)**, 0.6% of the crowded rows, far too few for 13 points. That leaves
coverage: S2 kept S1's 15k crowded tasks but spread them over 19 levels
instead of 11, ~790 per level against S1's ~1,360. S3 draws 26k crowded to
restore it (`results/logs/gen_s3.sh`); raising the cap is still done, as a
free fix for the 90. If E-crowded does not recover under S3, the remaining
suspect is the v2 surface itself — 18 native tools before crowding changes
the shape of a crowded prompt, and E-crowded's tasks are the older shape.

**E-known and demo_requests are S2R's, and they are different faults.**
Abort counts across every synthetic suite are 0 for both models — E-known's
−2.9 is ordinary forgetting from replaying only 20% of the corpus. But
demo_requests goes 0 → 9/65 aborts (13.8%), and every demo request is
actionable, so those are pure false abstains. The abstain trigger
generalised from "real turns" to "human-written text" and over-fires;
on the real suite the same fault costs 24/118 (20%) of should-act turns.

### Next

One rebuild, not another continuation — the two S2R faults (forgetting,
over-abstention) are both artifacts of warm-starting on a 25%-real mix:

1. Rebalance crowded coverage per level and raise `--max-len` above 6,459
   so the longest crowded rows keep their answers. This is the E-crowded
   fix and it is independent of everything else.
2. Fold the 900 real rows into the corpus **from the start** at a lower
   share (~5-8%, not 25%, and no 4x upsample), so abstention is learned
   alongside the curriculum rather than pushed on top of it.
3. Train fresh from the base, not from `lora_s2` — no replay, no forgetting.

`harness/real_train_build.py` regenerates the real rows (every target is
executed through the eval harness and kept only if it scores the metric it
teaches; 900 of 901 verified). Leakage is closed by construction: 0
turn-id overlap with the frozen slice and the 8 request texts appearing
verbatim in both are dropped.

**S3 passes 7 of 7** (6 of 7 as first scored; E-crowded cleared once the
grammar cap was lifted — see the correction below). Training fresh removed
S2R's forgetting (E-known is
the best it has been) and kept the real-request behaviour at full strength:
best routing, zero unnecessary destructive calls, 100% compile on real turns.

**LFM2.5-350M, same corpus, same eval:** 86% of S3's routing and 84% of its
abstention on real requests, fewer false abstains, and a perfect 240/240
on the synthetic abstain control — but 6 to 14 points behind on every
synthetic generalization suite, worst on restyled English (77.5 vs 91.0).
The size question resolves cleanly: capacity does not gate learning the
real-request trigger, it gates how far the model generalizes past the
corpus's phrasing. 350M would pass the real half of the rung and fail all
four synthetic bars.

**E-crowded is the miss, and it is now diagnosed.** Four hypotheses were
tested in order. Truncation: 90 of 53,849 S2 rows (0.17%), too few. Coverage:
restored to S1 parity in S3, no change (82.0). Prompt shape: E-crowded's
prompts carry a median 56 tools, S3's crowded training rows 55 — same.
Legacy-shape suite: S3 scored on `e_crowded_v2` (its own crowded recipe on
reserved worlds, levels 0–10, 300 rows) gets **57.7%** — worse than the
legacy suite, not better. The suite is not the problem.

The failure is field-symbol grounding at high symbol counts, and three
measurements pin it:

- 115 of 127 `e_crowded_v2` failures open with `UNKNOWN_FIELD`; goal by
  distinct `F`-symbols in the prompt: <100 → 100%, 100–124 → 78%,
  125–149 → 66%, **150+ → 46%**. Level 0, the only level with no field
  reference, is 28/28. The v2 prompts carry a median **151** distinct
  field symbols; the legacy suite's carry 113 — which is why S3 does worse
  on its own shape, and why S1 (whose worlds had far fewer fields) never
  hit this.
- All 115 are "in range but absent": the model never exceeds the highest
  field number present, it emits a plausible number that falls in a gap.
  It has learned the *range* of the symbol space, not *membership*.
- The tokenizer spells symbols digit by digit (`F157` = 4 tokens, `T18` =
  3). With 150+ candidates and a grammar that admits any `F[0-9]+`, one
  wrong digit is a legal, nonexistent symbol.

### Correction (2026-09-06): it was the harness, not the model

The third bullet above is wrong, and it was the tell. `agent_core.gbnf` did
**not** admit any `F[0-9]+` — it read `num ::= [0-9] [0-9]?`, so every symbol
above 99 was undecodable. On a context declaring 150+ fields the correct
answer could not be spelled at all: llama.cpp masks the third digit, the
sampler commits to the two-digit prefix (`F14` for `F142`), and the
typechecker reports `UNKNOWN_FIELD`. "In range but absent" was the truncated
prefix, not a guess.

Splitting each suite by whether its reference program needs a symbol ≥ 100
separates the two populations completely:

| suite | needs F≥100 | goal there | rest | goal there |
|---|---|---|---|---|
| E-crowded (300) | 44 | **0.0%** | 256 | 96.1% |
| `e_crowded_v2` (300) | 122 | **0.0%** | 178 | 97.2% |

Zero of 166. No other suite contains a single such task (E-known, E-foreign,
E-ood-english, `e_s2_levels`, `e_demo_requests`, E-real-sessions: 0 each),
which is why the fault surfaced only on crowded contexts — and why 8,017 of
S3's 62,841 training rows (12.8%) had targets the decoder could not emit.
The symbol-count curve, the level-0 exemption, and S1's immunity all follow
from the cap; none of them needed a capacity explanation.

**Fix (`harness/task_grammar.py`, PLAN.md §5 condition C4).** The grammar is
now rebuilt per task: `tool`/`field`/`const` become a digit trie over exactly
the symbols that task's context declares, so an undeclared symbol cannot be
decoded and a declared one always can. A trie rather than flat alternation
keeps live grammar stacks at the branching factor instead of one per symbol.
`num` in the base file also goes to three digits for callers with no symbol
table to hand (the browser demo). `run_a.py --grammar-mode` selects
`task` (default, logged as `A-grammar-task`) or `static` to reproduce older
runs.

Re-scored on the unchanged S3 GGUF:

| suite | static grammar | per-task grammar |
|---|---|---|
| E-crowded (300), bar ≥90 | 82.0 | **96.3** |
| `e_crowded_v2` (300) | 57.7 | **95.7** |

**S3 passes 7 of 7.** The 44 previously-impossible E-crowded tasks score
97.7%; the 122 in v2 score 92.6%. Both crowded numbers are now the best any
checkpoint has posted, and the S2 → S3 "regression" on E-crowded (94.7 →
82.0) was S2's worlds growing past 99 field symbols, not forgetting.

Two consequences for the rest of the table. LFM2.5-350M's E-crowded 76.3 is
depressed by the same cap and needs a re-score before the size comparison on
that row means anything. And "contiguous symbol renumbering" — the training-
side fix proposed below — is unnecessary: symbols were already contiguous
(`harness/context.py` assigns `F0…F(n-1)`), which is precisely why nothing in
the data explained the gaps.

**The demo over-abstention is the side effect to fix next.** S3 aborts 37
of 65 demo requests (NEEDS_INFO 27, NOT_FOUND 10), 13 of them level-0; the
same request text aborts in one task variant and succeeds in another, so
the trigger is reading the context, not the words. Folding the real
abstains in at x3 from scratch taught "terse human imperative on a small
world → NEEDS_INFO" harder than the S2R continuation did. Lever: keep the
658 actionable real rows at x3, drop the 242 real abstains to x1, and add
hand-written actionable requests on a non-coursebuilder world so human
phrasing is not a pure abstain cue.

Costs: S3 ~$13 (the pod fell through to secure cloud at $0.74/hr — check

### Smoke tests — untuned larger models as teacher candidates (2026-09-06)

Not scored arms. 25 tasks (7 E-known, 10 demo requests, 8 `e_crowded_v2`),
untuned, in-context, per-task grammar, two arms each: 0-shot (the SYSTEM
prompt's single example — the question the owner asked) and 4-shot
(`run_a.py --shots 4`). Scripts: `results/logs/smoke_lfm8b.sh`,
`results/logs/smoke_qwen36_27b.sh`.

| model | active / total | 0-shot | 4-shot | compile @4 | p50 gen |
|---|---|---|---|---|---|
| LFM2.5-8B-A1B (Q8) | 1B / 8B | 0/25 | **0/25** | 0% | 11–56 s |
| Qwen3.6-27B-A2.8B (IQ3 exp / Q4 head) | 2.8B / 27B | 2/25 | **6/25** | 32% | 32–137 s |
| *Qwen3.5-0.8B S3, tuned, for scale* | 0.8B | — | — | — | 5–15 s |

For reference the tuned 0.8B scores 99.0 on E-known and 95.7 on
`e_crowded_v2`. Neither untuned model is a usable teacher.

**One shot does not work on either.** The 8B never binds a register: it opens
`FILTER r0 …` against nothing (9 rows `UNBOUND`, 11 `PARSE_ERROR`). The 27B
manages 2 of 25, both on demo requests.

**Four shots separate them.** The 8B's format failure disappears — every
program parses — and nothing else improves: 0/25, with the diagnostics moving
to `TYPE_ERROR` (15), `MISSING_ARG` (5) and `UNKNOWN_FIELD` (4). It writes the
reference skeleton and picks the wrong symbols. The 27B converts: 6/25 goal
and 8/25 compiling, the only untuned model on file that produces executable
IR from examples alone.

**Crowded is a wall for both — 0/8 in every arm.** At 150+ declared field
symbols the untuned models have nothing to fall back on. The 27B's failures
there are `UNKNOWN_FIELD` (4 of 8 at 4 shots), which under the per-task
grammar can only mean a field that exists but belongs to a different entity
than the register holds — real mis-grounding, not a spelling error. This is
the suite where the tuned 0.8B scores 95.7.

**On human-phrased demo requests the 27B ties the tuned model** at 4/10 (S3
scores 4/10 on those same ten), but never abstains, where S3 abstains on 4 of
the 10. Ten tasks is too few to read as more than "not obviously worse".

**Two harness bugs surfaced here, both fixed, both affecting only untuned
arms.** (1) `line ::= indent? (… | "STOP" | …)` let the grammar stay live
after a column-0 terminator; tuned checkpoints put ~1.0 on EOG there, untuned
ones wrote a correct program and then wrote it again to the token cap. `line`
now requires an indent before STOP/RETURN/ABORT. Verified neutral on the
tuned model (S3: 39/40 on the same 40 `e_crowded_v2` tasks under both
grammars). (2) The 27B was first run under `--template chat`, which applies
the model's own chat template — that template ends the generation prompt with
an opening think tag unless `enable_thinking=false`, priming a reasoning
block the grammar forbids token by token. Under it the model wrote `IF r0 …`
without ever binding `r0`: 24 of 25 `UNBOUND`, 0 compiles, and four worked
examples did not move it. On `--template qwen` (the hand-rolled ChatML with
an explicit empty think block that the tuned Qwen arms use), same weights and
tasks: compile 0% → 43%, goal 0/7 → 2/7 on E-known. The LFM template has no
think prefix, so `chat` remains correct for it.

**Operational notes.** `lfm2moe` and `qwen35moe` both load in
llama-cpp-python 0.3.35 unpatched. The 27B GGUF is LM Studio's copy, loaded
through our own runtime: **LM Studio's OpenAI-compatible endpoint silently
ignores a GBNF grammar** — a grammar admitting only the literal `"HELLO"`
still returned `STOP` — so an eval through that API would be unconstrained
and incomparable to every other arm. Cost: two local downloads, no GPU. At
32–137 s/task on this CPU, any real teacher role is a GPU job.
