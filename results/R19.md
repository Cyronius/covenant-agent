# R19: decoys break lookalike choices; meaningless names do not

**Date:** 2026-09-27. **Branch:** `description-reading`. **Spend:** $1.01
(one A40, four runs at once, 1h45m). Balance $11.04.
**Plan:** `.claude/plans/option-split.md`.
**Picks up:** R18's open question: which of S6's three options breaks the
planner's choice between lookalike tools?

## The result

1. **Decoys break lookalike choices.** With a quarter of rows carrying decoys,
   A0 is right at lookalike choices 54% of the time, against 89% with none.
   That is the whole of S6's damage (R18: 56%).
2. **Decoys alone also break everything else; twin roles repair that part
   only.** Decoys without twin roles drop A0's other tool choices from 96%
   to 67%, and the plain exam to 42.0%, below S6 itself. Adding twin roles
   brings the other choices back to 95% but leaves lookalike choices at 54%.
   Decoys with twin roles score exactly what S6 did (53.9% against 54.4%).
3. **Meaningless names are nearly harmless.** A quarter of rows with
   meaningless names costs A0 about 4 points on the plain exam (74.4%, seed
   spread 2.3) and 9 points on lookalike choices (80%).
4. **Meaningless names cure SPt's name weakness but do not lift it past
   A0.** On meaningless-name tasks SPt goes from 52.0% to 75.0%; on real-name
   tasks it slips from 77.2% to 74.0%. Overall 74.2%, level with A0 on the
   same rows and below A0 without them.
5. **The best plain-exam model is unchanged:** A0 on the options-off rows,
   with `--backoff 3`, at 84.5%.

## Terms

As R18. In short:

- **A0:** the plain planner. **SPt:** the planner with R12's reading stages.
- **A lookalike pair:** two tools of the same shape for two different things
  ("fetch one spot", "fetch one advertiser").
- **Shape-unique choice:** the needed tool is the only one of its shape
  among the things in the task.
- **A decoy:** a second tool for the *same* thing with the same inputs and
  outputs but a different job ("get permit record" beside "get permit
  map"). S6 adds one or two to every tool that changes something.
- **Twin roles:** the working tool is drawn at random among a tool and its
  decoys, and the row is kept only if the request's wording fits the drawn
  one. Without twin roles the original tool is always the answer.
- **The three arms:** each is 25% new rows plus 75% options-off rows, as
  R17's `s6d25` mix. `dec` = decoys only, `dtw` = decoys + twin roles,
  `opq` = meaningless names on every new row, no decoys.

## 1. Exam scores

Plain 2,000 tasks, decoyed 2,000, flip 472. Greedy, with plain also under
`--backoff 3`.

| model | 25% of rows | plain | plain + backoff | decoyed | flip | test |
|---|---|---|---|---|---|---|
| A0 (R16, seeds 0 / 1) | none | 79.5 / 77.2 | 84.5 / 82.0 | 37.4 / 37.2 | 22.7 / 23.7 | — |
| A0 (R17) | all S6 options | 54.4 | 65.3 | 40.5 | 25.4 | — |
| A0 | **decoys only** | **42.0** | 50.9 | 35.4 | 10.8 | 95.7 |
| A0 | decoys + twin roles | 53.9 | 64.8 | 40.2 | 25.8 | 92.6 |
| A0 | meaningless names | 74.4 | 82.0 | 33.9 | 17.6 | 96.7 |
| SPt (R16) | none | 72.8 | 76.8 | 46.2 | 24.6 | — |
| SPt (R17) | all S6 options | 61.7 | 68.0 | 49.6 | 38.8 | — |
| SPt | meaningless names | 74.2 | 79.8 | 43.6 | 22.2 | 94.0 |

The test split's mix differs between arms, so its column is not comparable
across rows.

- **Decoys + twin roles reproduce S6 to within half a point on every exam.**
  The meaningless names in S6 add nothing measurable on top.
- **Decoys alone do more damage than S6.** Even level 0, a single call, falls
  to 48.9% (`fail_kinds_dec25_A0_plain.log`), and 85% of all failures are the
  wrong tool.
- **A0 gets nothing on the decoyed exam from any arm** (34–40%), as in R14
  and R17.
- **The flip skill comes from twin roles.** Decoys alone halve A0's flip score
  (10.8%); twin roles restore it to the no-S6 level. Only SPt with full S6
  goes beyond that (38.8%).

## 2. Tool choice, teacher-forced

`results/logs/tool_choice_r18.py` → `s6opt/tool_choice.log`. The same 800
plain-exam tasks as R18.

| model | lookalike choices | shape-unique choices |
|---|---|---|
| A0, none (R18, seeds 0 / 1) | 89.2 / 89.0 | 96.4 / 95.2 |
| A0, all S6 25% (R18) | 55.8 | 93.4 |
| **A0, decoys only** | **54.2** | **66.5** |
| **A0, decoys + twin roles** | **53.8** | 94.6 |
| A0, meaningless names | 80.4 | 95.8 |
| SPt, none (R18) | 87.8 | 93.1 |
| SPt, meaningless names | 83.4 | 96.0 |

Where the wrong picks at lookalike pairs go:

| model | the lookalike | a generic tool | same thing, other tool | other thing |
|---|---|---|---|---|
| A0, decoys only | 61% | 22% | 9% | 7% |
| A0, decoys + twin roles | 54% | 25% | 12% | 9% |
| A0, meaningless names | 91% | 3% | 3% | 3% |
| SPt, meaningless names | 42% | 2% | 23% | 34% |

- **Decoys, with or without twin roles, take lookalike choices to 54%.**
  This is R18's damage, and the drift toward generic helper tools (22–25%)
  comes with it.
- **Decoys alone damage shape-unique choices too (67%).** Twin roles remove
  that damage completely and leave the lookalike damage exactly as it was.
  So there are two separate harms, and twin roles fix only the second.
- **Meaningless names cost 9 points on lookalike choices, with a clean error
  pattern.** Almost every wrong pick is the other tool of the pair, not a
  generic helper. This is an ordinary accuracy loss, not R18's breakdown.

## 3. SPt and meaningless names

`results/logs/names_gap_r18.py`.

| model | real-name tasks | meaningless-name tasks | gap |
|---|---|---|---|
| A0, none (seeds 0 / 1) | 79.3 / 77.8 | 80.1 / 74.7 | −0.8 / +3.1 |
| SPt, none | 77.2 | 52.0 | +25.3 |
| A0, meaningless names | 74.2 | 75.3 | −1.1 |
| **SPt, meaningless names** | **74.0** | **75.0** | **−1.0** |

The 25-point gap is gone. SPt pays for it with about 3 points on real-name
tasks, so it now matches A0 trained on the same rows, not A0 on the
options-off rows. R18's expectation that this run would give SPt A0's plain
score with its own decoyed-exam edge did not hold: its decoyed score fell
from 46.2% to 43.6%.

## 4. Why decoys would do this: a hypothesis, one rough check

A decoy has the same inputs and outputs as the real tool. The planner can
only tell them apart from the request's wording. If the request does not
name what separates them, the row teaches "choose this one" with no reason
the planner can see.

A rough check (scratch script, word overlap between the request and each
tool's name and description, 3,000 rows of each training shard, calls whose
tool has a same-signature sibling):

| shard | request favours the answer | tie | request favours a decoy |
|---|---|---|---|
| decoys only | 33% | 60% | 7% |
| decoys + twin roles | 40% | 53% | 7% |

By this crude measure, in most decoyed calls the request does not favour the
right tool over its decoy. A planner taught on such rows could learn that
wording does not settle same-shape choices. That would explain the lookalike
damage in both arms. The check does not explain why decoys alone also break
shape-unique choices. One guess: without twin roles the original tool always
wins, so the planner could learn a habit about which tool "looks original"
instead of reading the request. That is not tested.

The overlap measure is word-level and blind to synonyms, so its tie rate is
an upper bound on real ambiguity. It is not in `results/logs/`.

## What this settles

- **S6's plain-exam cost is decoys.** Meaningless names are cleared. Twin
  roles are not the cause; they are a partial cure.
- **SPt's R16 deficit is fixed by meaningless names alone**, but that brings
  it level with A0, not past it.
- **Nothing trained so far beats A0 on options-off rows for the plain exam,
  or SPt with 25–50% S6 for the decoyed exam.** The two exams still want
  different corpora.

## Next

1. **Test the ambiguity hypothesis on the laptop first ($0).** Replace the
   word-overlap check with the generator's own `domains.request_fits`
   against every decoy: for each decoyed call, does the request fit the
   answer's templates and not a decoy's? If most decoyed rows fail that
   test, the hypothesis stands.
2. **If it stands, a data fix (one pod run, about $1, needs a go-ahead):**
   decoys + twin roles, keeping a decoyed row only when its request fits the
   answer and no decoy. If lookalike choices stay near 89% while the decoyed
   exam rises, decoys can be taught without the damage.
