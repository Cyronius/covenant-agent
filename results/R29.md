# R29: with ELECTRA as its only reader, the tiny planner holds its clean scores; roles add about a point; dropping the request's words costs 2-5

**Date:** 2026-10-04. **Branch:** `description-reading`. **Spend:** about $1.70
(a secure A40 at $0.49/hr for about 3.3 hours, plus a few minutes on a faulty
L40S host); about $2.40 for the whole reader plan (R27 included).
**Plan:** `.claude/plans/electra-only-reader.md`, steps 2 and 3. The owner
dropped Ternlight ("remove anything that follows ternlight. let's just try
electra stuff") and said "do it" to each step.

**Terms.** *Reader*: what turns each text the planner sees (tool description,
request, constant, field) into a vector. Here it's the ternary ELECTRA-small
with R27's head n, 6.6 MB plus a 1.5M-number head. *One pass*: ELECTRA reads
the request once, and each piece of it (a role's words, a 4-word chunk) is
pooled out of that pass. *Role slots*: the request's action, object,
destination, source, condition, time and amount, tagged by ELECTRA. *Goal*:
the program run in the sandbox leaves the world as the reference does.
*Greedy*: one decode, no retries. *Backoff 3*: on a compile failure, up to 3
runner-up tools at the failing call.

## The result

The same recipe as R23 (A0 planner, the reader frozen, 12 epochs) on the same
cluttered corpus (`clt_train`), with every reader vector ELECTRA's. Three
arms, two seeds each. Greedy goal %:

| | plain | cluttered | decoyed | flip | test |
|---|---|---|---|---|---|
| chunks (`c0_EL`, seeds 0 / 1) | 66.0 / 67.9 | 68.0 / 69.6 | 45.9 / 46.2 | 37.5 / 38.1 | 88.8 / 89.8 |
| **roles + chunks** (`c0_ESC`) | **67.6 / 68.0** | **70.5 / 70.6** | **47.6 / 46.6** | **39.6 / 37.7** | **89.7 / 90.7** |
| roles + chunks, no request words (`c0_ESCV`) | 65.2 / 66.2 | 67.7 / 67.5 | 44.0 / 43.0 | 36.7 / 37.1 | 85.8 / 85.4 |
| R23's Ternlight reader (`clt_RD`, seeds 0 / 1) | 67.0 / 69.1 | 61.6 / 63.8 | 47.1 / 46.6 | 39.6 / 35.2 | 89.6 / 90.6 |

1. **Dropping Ternlight cost nothing measurable on the clean exams.**
   Against R23's Ternlight-reader planner, the roles arm is level on plain
   (67.8 vs 68.1, two-seed means), decoyed (47.1 vs 46.9), flip (38.7 vs
   37.4) and test (90.2 vs 90.1).
2. **It's 8 points better on cluttered contexts (70.6 vs 62.7), but that is
   not ELECTRA's win alone.** These runs also give the planner reader vectors
   for every constant and field (C0), which R23's didn't. The run that would
   separate the two, C0 with Ternlight (`c0_RL`), was never run, and the owner
   chose not to add it.
3. **Roles help a little, in every exam.** Roles + chunks beats chunks alone
   by 0.9 (plain), 1.8 (cluttered), 1.1 (decoyed), 0.9 (flip) and 0.9 (test)
   on the two-seed means; seed by seed it's ahead in 9 of 10 pairs. Each gap
   is within what two seeds can resolve, so: a small, consistent gain, not a
   proven one. Destination and source, the roles Ternlight couldn't read, are
   in only 4% and 2% of training requests (R26), so this exam barely tests
   them.
4. **The request's own words still matter.** With them dropped, the planner
   loses 2.1 (plain), 3.0 (cluttered), 3.6 (decoyed), 1.8 (flip) and 4.6
   (test). The vectors carry most of the request, not all of it.

**Backoff 3, one seed so far** (`c0_EL`): plain 68.8 (greedy 66.0), cluttered
71.0 (68.0). R23's `clt_RD`: plain 72.2, cluttered 66.6. Backoff added 2.8
points here against R23's 5.2 on plain; one seed can't say whether that's
real.

## How it ran

- **Step 2** (`electra_cache.py`): on a pod, ELECTRA read the 180,698 texts
  the cache already indexes (descriptions, requests, constants, fields) one at
  a time, and the 29,579 distinct requests in one pass each (260,951 pieces);
  the laptop applied that to `data_cache_c0` as `data_cache_c0e` (chunks) and
  `data_cache_c0esc` (7 slots, then chunks). A piece's vector depends on its
  request, so each (request, piece) has its own table row. The live path
  (`play.py --reader-live electra`) gives the same vectors on the CPU (cosine
  above 0.995; `test_reader_lines.py`).
- **Step 3** (`run_c0e.sh`): six arms side by side on one A40 (43 of 46 GB),
  greedy generation on the holdout's four halves and the test split. Best
  validation loss: chunks 0.018 / 0.021, roles 0.020 / 0.020, no request words
  0.026 / 0.030.
